# TailSync 2.3.1

安全加固、稳定性与正确性修复。**无新增功能**：线协议仍为 v4、数据库 schema 仍为 v11，已配对设备无需重新配对即可升级。

---

## 安全与隐私

- **局域网模式不再放行 Tailscale 地址。** `lan_only` 之前会把 Tailscale 的 IPv6 ULA 前缀 `fd7a:115c:a1e0::/48` 当成普通 ULA 放行（它数学上落在 `fc00::/7` 之内），使局域网模式的安全隔离失效。现在 Tailscale 地址被优先且排他地判定，其他 ULA、链路本地与回环保持原语义。
- **同名不同公钥不再静默替换信任锚。** 之前用相同主机名配对一台新设备会直接覆盖旧设备已固定的公钥。现在会拒绝并提示先解除旧配对；相同公钥的重复配对仍然幂等。
- **发现阶段的地址不再写入持久路由。** 局域网 mDNS/UDP 广播是未认证的，之前可被伪造用来改写已信任设备保存的路由。现在发现结果只作为本轮的临时连接候选；持久地址只在完成固定公钥验证的握手之后更新。
- **匿名流量不再能锁定配对窗口。** 以前局域网内未认证的对端只要反复发起握手再立即断开，就能把失败计数打满、让配对窗口进入 `Locked` 关闭。现在只有**用户已在本机确认**的会话上的协议异常才计入锁定预算；未确认会话断开只释放槽位，且已确认的槽位不可被新会话挤掉。
- **配对读帧的取消安全。** 配对窗口状态变化时不再打断半个帧的读取，消除由此造成的随机握手失败与字节流错位。

## 稳定性与崩溃

- **修复图片缩略图导致的内存爆炸。** 把普通文件的历史 ID 传给图片缩略图接口时，之前会把整份文件（最高 5 GiB）解密进内存并持有数据库锁，造成 OOM 或界面卡死。现在在解密之前先按元数据校验条目类型与声明大小（仅图片，且不超过 64 MiB）。

## 传输与存储正确性

- **断点续传不再被重复记账。** 接近配额时续传会被错误拒绝，因为预检把磁盘上已有的 `.part` 前缀又算了一遍。现在只预留「剩余待写明文 + 完整加密副本上界 + 安全余量」，并把 `.part` 的抵扣绑定到落盘批次清单与续传 sidecar，避免同名但属于其他来源的 `.part` 被误用。
- **配额淘汰不再删了历史却没释放空间。** 之前淘汰内联文本行后数据库文件不会缩容，于是误报「已清理但未回收空间」并永久拒绝入站传输。现在只淘汰持有外部加密文件的行；当仅剩内联行、继续删除也无法释放物理空间时，给出准确的空间不足提示，而不是白白删掉历史。
- **提交后的清理更健壮。** 删除提交后，每个引用查询、路径解析与文件删除分别容错并记录日志；WAL 检查点繁忙不再被当成「删除失败」，也不会因此让界面误判。

## 连接与投递

- **大文件传输不再因路由微变被中断。** 连接池之前按「动态目标地址 + 主机名」标识 worker，后台网络自省导致首选 IP 轻微重排时会就地杀死 worker、回滚传输。现在按主机名复用存活 worker，并把最新候选通过通道推给下一次重连使用。
- **ACK 超时不再在同一连接上重放。** 重放时，上一次尝试遗留的重复 ACK 会被误读为本次 ACK 并升级成协议错误，造成连接反复震荡。现在结束本次尝试，由 worker 在新的认证连接上按既有去重与续传协议重试。
- **投递失败的重连加入退避。** 之前握手成功但投递立即失败时会以毫秒级速度死循环重连，占满 CPU 并卡住设置保存。现在使用可被关闭信号或新任务打断的退避。
- **心跳校验命令与序号。** 旧连接的业务 ACK 不会再被当作心跳确认或下一个业务帧的确认。
- **竞速不再交固定延迟税。** 首选 LAN 即使 1 ms 内就报错，备用 Tailscale 也要空等 300 ms 才能起跑。现在首选快速失败会立即释放后备；同时避免在另一个即时候选仍在连接时过早起跑。

## 界面与本地网络

- **本机局域网地址不再显示为 `0.0.0.0` 或 VPN 隧道地址。** 改为从本机网卡枚举中选取（优先物理私网 IPv4），并过滤 down/p2p 接口；没有可确认地址时不再伪装成一条已连接路由。
- **候选排序更符合直觉。** 改为「实测在线 → 延迟 → 接口优先级 → 地址类别 → 数值 IP」，避免 APIPA 或回环地址靠字符串排序抢占首选地址；自动模式下 `tailscale_ip` 也只从 Tailscale 候选推导，不再被 LAN 地址覆盖。
- **修复「关闭时停止了向 … 发送剪贴板内容」的误报。** 这条提示以前在对端离线、连接重试、文件批次重试时也会被记录，因而几乎常驻在历史页。现在它只在**真实退出应用且确有在途剪贴板帧被丢弃**时才记录；文件传输使用自己独立的失败提示。
- **macOS 长轮询在客户端断开时会被取消**，及时归还连接许可，不再占用到轮询超时。
- **运行时快照的平台校验收敛为 `macos`**，避免连到非 macOS 守护进程时解码失败、触发看门狗反复重启。

## 本次未包含

- **配对持久化的 pending/active 一致性（单边孤儿）仍会存在**：需要设置结构升级与双端 UI 配合，安排在后续版本。
- 文件控制帧与即时事件队列的隔离（需先做饱和测量）、分块处理的锁范围优化：按「先测量、后改动」处理。
- 关于「握手第二报文泄露主机元数据」的报告已核实不成立（第二报文负载本身已加密）。
