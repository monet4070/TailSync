# macOS O08 修复测试与验收方案

日期：2026-09-24
适用范围：macOS 原生构建、Swift 客户端、Community 应用包，以及与同版 Windows O08 设备的互通。此文档是执行计划；未在真实 Mac 与成品包上完成的项目不得标记为通过。

本轮发行目标为个人开发者的 Community 构建（2026-09-24 用户确认）。Community 使用 ad hoc 签名，不以 Developer ID、公证或 Gatekeeper 认可作为通过条件；应记录这些检查的实际结果并按社区分发说明验证安装和启动。若以后选择 trusted 发行层级，必须单独完成正式签名和公证验收。设备互通使用用户指定的 Iroh 路径；本轮不以 LAN/Tailscale 覆盖作为 M4/M8 的通过条件。

2026-09-24 用户决定跳过 M9 的全部干净账户测试，本轮 M9 记为 `SKIPPED`，不记为 `PASS`，也不参与本轮 GO 门槛。已有 Community DMG 的构建、签名、结构和当前账户启动检查仍保留原始结果；干净账户首装、权限拒绝/恢复、旧数据升级的风险未经实测，不推断其通过。

2026-09-24 用户确认 M4 不再重复相同大文件/断线操作 3 次；以发送端强制退出和对端网络断开这两种不同故障的真实设备结果、接收端续写证据及最终 SHA-256 作为本轮门槛。记录实际轮次，不把它表述为原三次重复已完成。

2026-09-24 用户取消本轮对前面版本的兼容性要求。M2 的旧 daemon 文本响应、M3 的 wire v4/未声明版本回退、M8 的上一发行版互通均移出通过门槛；已有结果留档，但不据此声称兼容。新版双端仍须验证 v5 会话、能力开关、双向传输、配对授权和断线恢复。此范围变更仅调整验收，不要求移除产品中的兼容代码。

## 1. 验收目标

确认 O08 修复在 macOS 实际发行链路中可用：稳定错误契约在 Tauri 与本地 socket API 中一致；同版 Mac/Windows 设备建立 wire v5 会话并协商能力；文件滑窗与压缩图片分片在双端支持时生效，断线、能力关闭和异常输入时安全处理；应用可构建、运行并正常退出。干净账户安装与旧数据升级属于本轮已跳过的 M9。

若以后恢复 M9，干净用户安装和升级测试使用专用测试账户；其他本机检查使用独立数据目录和无敏感内容的剪贴板样本。每项记录 PASS/FAIL/BLOCKED/SKIPPED、复现步骤、时间、日志位置及问题编号。日志和截图在脱敏后保存；不得把认证令牌、私钥、剪贴板隐私内容写入报告。

本机继续验收时使用现有登录钥匙串与独立 `TAILSYNC_DATA_DIR`、独立 API socket/token；不得创建临时钥匙串或修改用户的全局钥匙串搜索列表与默认项。测试前后核对列表和默认项。若以后恢复 M9，干净用户安装及旧数据升级须在真实独立用户环境完成，不把独立数据目录的冒烟检查当成 M9 完整通过。

## 3. 构建与自动化检查

在仓库根目录的 macOS 工作副本执行：

```bash
cd macos
bash scripts/check_macos_sources.sh
```

此脚本检查 Rust 格式、共享 Core 与 macOS Tauri Rust 的 clippy/test、Swift 包测试和 release build，以及 Windows/macOS 跨平台契约同步。保存完整标准输出和退出码。任何一步失败均为 NO-GO，修复后从失败步骤及完整脚本复跑。

按 Community 发行配置构建后，在安装前检查包身份：

```bash
cd macos
codesign --verify --deep --strict TailSync.app
spctl --assess --type execute --verbose=2 TailSync.app
shasum -a 256 <发行包路径>
```

本轮使用 `TAILSYNC_RELEASE_TIER=community` 执行仓库提供的打包检查。以后采用受信任发行级别时再使用 `trusted`：

```bash
cd macos
TAILSYNC_RELEASE_TIER=trusted bash scripts/verify_macos_bundle.sh
```

如使用社区签名配置，按对应发行级别执行 `verify_macos_bundle.sh`；不要把 ad hoc 签名检查结果写成公证通过。记录 `spctl` 与 `stapler` 结果及实际分发方式。

## 4. 功能验收矩阵

| ID | 场景与步骤 | 通过标准 |
|---|---|---|
| M1 稳定错误契约 | 用 macOS UI/Tauri 命令及本地 socket API 分别触发无效参数、资源不存在、未授权、协议不兼容、存储不可用和内部错误。检查请求/响应，再观察界面中英文错误展示。 | 普通命令返回版本化稳定 envelope 与受支持的固定码/消息键；UI 使用本地化文案；不泄露路径、堆栈、令牌或内部细节。socket 的 `supports_stable_errors` 为 true。 |
| M2 预览错误 | 对当前 daemon 的预览接口提交错误数据、缺失资源和超限输入。 | 预览走专用错误结构和固定公开文案；未知错误安全降为 `internal_error`，应用不崩溃。旧 daemon 文本响应仅保留既有测试记录。 |
| M3 v5 协商 | 同版 Mac/Windows O08 通过 Iroh 配对、断开重连及重启；默认启用与分别关闭能力后建立新连接，抓取脱敏会话诊断。 | 业务会话选择 wire v5；双方文件滑窗及图片分块能力按每条连接重新协商，重启后能恢复。配对阶段的 v4 握手不等于业务会话降级。 |
| M4 文件滑窗 | 双方新版本通过 Iroh 传小文件、超过 4 MiB 文件和大文件；校验 SHA-256。再在确认中途断网/强制退出发送端，重启后重连续传。 | 协商开启时最多 4 个 1 MiB 分片在途；内容、文件名及大小正确；续传从确认偏移恢复，无重复/截断/损坏。未协商时逐片确认传输仍成功。 |
| M5 压缩图片分片 | 传高重复像素图片（应能压缩）和噪声图片（压缩收益低）；覆盖多种尺寸，校验接收图片像素/哈希及剪贴板与历史。 | 可压缩素材使用分片后正确重组；低收益素材安全回退原始 RGBA；分片完成前不写入剪贴板/历史；UI 展示内容正确。 |
| M6 图片异常输入 | 在测试构建/协议夹具中注入乱序、重复、缺片、摘要错误、伪造超大尺寸、超限分片及解压膨胀输入。 | 有效帧长内的坏图片分片被拒绝，不崩溃、不写入部分图像，返回固定 `invalid_image_chunk`，仅关闭本会话的压缩图像能力；新会话可恢复。若帧头声明长度超过协议上限，解析器须在读取或分配大载荷前断开连接，重连后可恢复。缺片且没有后续帧时可等待至连接超时；不得产生部分图像。 |
| M7 能力关闭开关 | 分别设置 `TAILSYNC_DISABLE_FILE_WINDOW=1`、`TAILSYNC_DISABLE_IMAGE_CHUNKS=1` 启动 daemon；再同时设置两项。检查握手声明和传输行为。 | 对应能力不被宣告且传输走兼容路径；开关互相独立；未设置时默认能力按发行构建启用。每次修改环境变量后完整退出并重新启动 daemon。 |
| M8 新版真实互通回归 | macOS O08 与 Windows O08 通过 Iroh 双向互传文本、PNG/截图和文件，并验证配对授权、重启及断线恢复。 | 双向内容一致，未授权对端不能访问数据；错误与断线后可恢复。上一发行版互通不参加本轮验收。 |
| M9 安装、权限与生命周期 | 在干净 macOS 用户环境安装发行包、首次启动、授予/拒绝本地网络权限、退出重启；在已有旧版数据环境执行升级。 | DMG/应用可按发行说明启动；权限拒绝时给出可理解提示并可在系统设置恢复；helper、daemon、登录项/端口无重复残留；升级保留设置、配对和历史且数据可读。 |
| M10 持续运行与资源 | 连续运行一个记录起止时间的验收窗口；其间传输混合文本、图片、文件并多次锁屏/唤醒、切换网络、断连重连。 | 无崩溃、死锁、持续增长的内存/句柄、重复通知或数据损坏；恢复后同步继续。记录实际时长、采样间隔、起始/峰值/结束内存与句柄，以及错误日志。 |

M1 中，主动配对的不兼容握手由 `start_pairing` 命令返回固定 `protocol_incompatible`；已配对设备在后台重连时遇到不兼容握手，`get_peers` 保持设备列表可用，并通过每设备的 `required_protocol_version` 提示升级。两条路径分别用隔离协议夹具和实际 SwiftUI 组件验证，不能把后台故障强行变成整个设备列表命令失败。

## 5. 回归细节与诊断

- 至少准备 3 个文件：小文件、4 MiB 以上文件、接近产品允许上限的文件；记录字节数与 SHA-256。本轮断线续传覆盖发送端强制退出和对端网络断开两种不同故障，记录接收端已有字节、恢复后续写和最终 SHA-256；按用户决定不再重复相同操作 3 次。
- 图片准备 PNG 截图/纯色图及不可压缩噪声图；至少测试小图、常见截图和协议允许的最大合法尺寸。拒绝非法尺寸的用例不得占用大量内存。
- 错误用例逐一核对稳定码、版本字段、公开文案键和敏感字段；记录具体命令/API 名称，避免仅以界面弹窗作为契约证据。
- 网络切换期间记录连接建立、协商版本、已确认文件偏移、回退原因和重连时间。网络包可用于定位，但报告中仅保留脱敏后的必要元数据。
- 验收包必须与待发布 commit 一致。检查文件哈希、版本号和签名身份，确认测试后没有替换二进制。

## 6. 通过门槛与结论

本轮 M1–M8 和 M10 必须 PASS；M9 按用户决定记为 SKIPPED，不参与本轮 GO 门槛。原生 macOS `check_macos_sources.sh`、发行包结构检查与 Community ad hoc 签名检查必须通过。Community 不要求公证通过；`spctl` 拒绝未公证包应按预期记录，并验证发行说明中的社区安装步骤。M3–M8 至少要有真实 macOS 与真实 Windows O08 对端结果，Core 的单元测试或模拟网络结果不能替代设备互通。旧版兼容不在本轮门槛内。任何数据损坏、越权访问、崩溃、错误契约泄露内部信息、协商不一致、续传错误或安全边界绕过均直接 NO-GO。

结论填写：`GO / NO-GO`；未跑项目填写 `BLOCKED` 并注明设备、版本或条件。附测试日志、脱敏截图、发行包哈希、对端版本和所有失败问题链接。只有修复后在相同构建配置上复测通过，才能关闭对应失败项。
