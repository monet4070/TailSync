# macOS O08 修复测试与验收方案

日期：2026-09-24
适用范围：macOS 原生构建、Swift 客户端、签名应用包，以及与 Windows/旧版设备的互通。此文档是执行计划；未在真实 Mac 与成品包上完成的项目不得标记为通过。

## 1. 验收目标

确认 O08 修复在 macOS 实际发行链路中可用：稳定错误契约在 Tauri 与本地 socket API 中保持兼容；新旧设备按协商结果选择 wire v4/v5；文件滑窗与压缩图片分片在双端支持时生效，断线、降级和异常输入时安全回退；应用可干净安装、升级、运行并正常退出。

## 2. 验收环境与记录

## 3. 构建与自动化检查

在仓库根目录的 macOS 工作副本执行：

```bash
cd macos
bash scripts/check_macos_sources.sh
```

此脚本检查 Rust 格式、共享 Core 与 macOS Tauri Rust 的 clippy/test、Swift 包测试和 release build，以及 Windows/macOS 跨平台契约同步。保存完整标准输出和退出码。任何一步失败均为 NO-GO，修复后从失败步骤及完整脚本复跑。

针对正式签名发行候选包，按发行配置构建后，在安装前检查包身份：

```bash
cd macos
codesign --verify --deep --strict TailSync.app
spctl --assess --type execute --verbose=2 TailSync.app
shasum -a 256 <发行包路径>
```

受信任发行级别还需通过仓库提供的打包检查：

```bash
cd macos
TAILSYNC_RELEASE_TIER=trusted bash scripts/verify_macos_bundle.sh
```

如使用社区签名配置，按对应发行级别执行 `verify_macos_bundle.sh`；不要把 ad hoc 签名检查结果写成公证通过。记录 `spctl` 与 `stapler` 结果及实际分发方式。

## 4. 功能验收矩阵

| ID | 场景与步骤 | 通过标准 |
|---|---|---|
| M1 稳定错误契约 | 用 macOS UI/Tauri 命令及本地 socket API 分别触发无效参数、资源不存在、未授权、协议不兼容、存储不可用和内部错误。检查请求/响应，再观察界面中英文错误展示。 | 普通命令返回版本化稳定 envelope 与受支持的固定码/消息键；UI 使用本地化文案；不泄露路径、堆栈、令牌或内部细节。socket 的 `supports_stable_errors` 为 true。 |
| M2 预览错误兼容 | 对预览接口提交错误数据、缺失资源和超限输入；另以旧版 daemon 的文本错误响应运行兼容验证。 | 预览仍走专用错误结构和固定公开文案；旧文本错误可兼容分类；未知错误安全降为 `internal_error`，应用不崩溃。 |
| M3 v4/v5 协商 | 依次连接旧版未声明 wire 的 macOS/Windows 对端、仅支持 v4 的新旧混合对端、双方支持 v5 的对端；断开后重新连接。抓取脱敏握手/协议诊断信息。 | 未声明或不匹配时选择 v4；双方明确支持时选择 v5；能力按每条连接重新协商。握手与配对仍兼容 v4，不出现单边切换导致的连接中断。 |
| M4 文件滑窗 | 双方新版本在 LAN 与 Tailscale 各传小文件、超过 4 MiB 文件和大文件；校验 SHA-256。再在确认中途断网/强制退出发送端，重启后重连续传。 | 协商开启时最多 4 个 1 MiB 分片在途；内容、文件名及大小正确；续传从确认偏移恢复，无重复/截断/损坏。未协商时逐片确认传输仍成功。 |
| M5 压缩图片分片 | 传高重复像素图片（应能压缩）和噪声图片（压缩收益低）；覆盖多种尺寸，校验接收图片像素/哈希及剪贴板与历史。 | 可压缩素材使用分片后正确重组；低收益素材安全回退原始 RGBA；分片完成前不写入剪贴板/历史；UI 展示内容正确。 |
| M6 图片异常输入 | 在测试构建/协议夹具中注入乱序、重复、缺片、摘要错误、伪造超大尺寸、超限分片及解压膨胀输入。 | 拒绝坏消息且不崩溃、不写入部分图像；返回固定 `invalid_image_chunk` 协议错误；仅关闭本会话的压缩图像能力，后续可通过新会话恢复。 |
| M7 能力关闭开关 | 分别设置 `TAILSYNC_DISABLE_FILE_WINDOW=1`、`TAILSYNC_DISABLE_IMAGE_CHUNKS=1` 启动 daemon；再同时设置两项。检查握手声明和传输行为。 | 对应能力不被宣告且传输走兼容路径；开关互相独立；未设置时默认能力按发行构建启用。每次修改环境变量后完整退出并重新启动 daemon。 |
| M8 真实互通回归 | macOS 新版分别与 Windows 新版及上一发行版互传文本、PNG/截图和文件；覆盖局域网与产品实际支持的远程路径。 | 双向内容一致，配对/授权边界正确，旧版互通按 v4 与逐片/原图回退；错误与断线后可恢复。 |
| M9 安装、权限与生命周期 | 在干净 macOS 用户环境安装发行包、首次启动、授予/拒绝本地网络权限、退出重启；在已有旧版数据环境执行升级。 | DMG/应用可按发行说明启动；权限拒绝时给出可理解提示并可在系统设置恢复；helper、daemon、登录项/端口无重复残留；升级保留设置、配对和历史且数据可读。 |
| M10 持续运行与资源 | 连续运行一个记录起止时间的验收窗口；其间传输混合文本、图片、文件并多次锁屏/唤醒、切换网络、断连重连。 | 无崩溃、死锁、持续增长的内存/句柄、重复通知或数据损坏；恢复后同步继续。记录实际时长、采样间隔、起始/峰值/结束内存与句柄，以及错误日志。 |

## 5. 回归细节与诊断

- 至少准备 3 个文件：小文件、4 MiB 以上文件、接近产品允许上限的文件；记录字节数与 SHA-256。大文件和断线续传需各重复 3 次。
- 图片准备 PNG 截图/纯色图及不可压缩噪声图；至少测试小图、常见截图和协议允许的最大合法尺寸。拒绝非法尺寸的用例不得占用大量内存。
- 错误用例逐一核对稳定码、版本字段、公开文案键和敏感字段；记录具体命令/API 名称，避免仅以界面弹窗作为契约证据。
- 网络切换期间记录连接建立、协商版本、已确认文件偏移、回退原因和重连时间。网络包可用于定位，但报告中仅保留脱敏后的必要元数据。
- 验收包必须与待发布 commit 一致。检查文件哈希、版本号和签名身份，确认测试后没有替换二进制。

## 6. 通过门槛与结论

所有 M1–M10 必须 PASS；原生 macOS `check_macos_sources.sh`、发行包结构检查与适用的签名/公证检查必须通过。M3–M8 至少要有真实 macOS 与真实 Windows/旧版对端结果，Core 的单元测试或模拟网络结果不能替代设备互通。任何数据损坏、越权访问、崩溃、错误契约泄露内部信息、协商不一致、续传错误或安全边界绕过均直接 NO-GO。

结论填写：`GO / NO-GO`；未跑项目填写 `BLOCKED` 并注明设备、版本或条件。附测试日志、脱敏截图、发行包哈希、对端版本和所有失败问题链接。只有修复后在相同构建配置上复测通过，才能关闭对应失败项。
