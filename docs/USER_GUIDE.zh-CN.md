# TailSync 实用指南

> 适用版本：TailSync 2.2.0，线协议 v4，数据库 schema v9
> 支持平台：macOS、Windows

TailSync 用来在自己的 macOS 和 Windows 设备之间同步剪贴板。两端配对后，在一台设备上复制文本、图片或文件，内容会自动写入另一台设备的系统剪贴板，并保存在各自的本地历史中。

TailSync 不依赖中心化云剪贴板：它优先使用局域网直连，必要时通过 Tailscale 通信。配对设备通过固定身份和加密会话互相认证。

## 一分钟快速上手

1. 在两台设备上启动 TailSync，确认菜单栏或系统托盘中能看到 TailSync 图标。
2. 分别打开“设置 → 连接与设备”，将连接方式设为“自动”。
3. 在两端点击“允许配对”。配对窗口会在 120 秒后自动关闭。
4. 等待设备出现在列表中，在其中一端点击“配对”。
5. 核对两端显示的六位验证码和设备指纹；完全一致时，双方都点击“验证码一致”。
6. 等设备状态变成“可同步”或“已连接”。
7. 在任意一端复制一段无敏感信息的测试文本，再到另一端粘贴。

如果设备没有出现，请先查看[连接与配对排障](#连接与配对排障)，不要反复删除配对信息。

## 安装与首次启动

### 从可信来源安装

建议只使用项目 GitHub Release 中的安装包，并核对随发布提供的 SHA-256 校验文件。当前默认发布物属于 Community Release：更新包仍有 TailSync 私钥签名、校验和与降级保护，但 macOS 安装包未公证，Windows 安装包没有商业代码签名，因此系统可能显示 Gatekeeper 或 SmartScreen 提示。

只有在确认安装包来源和校验值正确后，才应按照系统提供的正常流程继续打开。不要关闭 Gatekeeper、SmartScreen、防火墙或其他系统安全功能。

### TailSync 在哪里

TailSync 是常驻型工具，通常不会一直显示主窗口：

- macOS：位于顶部菜单栏。左键点击图标打开历史记录；右键点击显示功能菜单。
- Windows：位于任务栏通知区域。左键点击图标打开历史记录；右键点击显示功能菜单。

托盘或菜单栏菜单可以：

- 暂停或恢复同步；
- 打开历史记录；
- 打开设置；
- 查看正在传输的文件、进度和目标设备；
- 停止当前文件批次；
- 查看存储不可用警告；
- 在设置中查看版本并检查更新（Windows、macOS）；
- 退出 TailSync。

关闭历史记录或设置窗口不会退出 TailSync。需要彻底停止服务时，请从菜单选择“退出 TailSync”。

## 连接两台设备

### 选择连接方式

在“设置 → 连接与设备”中选择连接方式：

| 模式 | 适用场景 | 注意事项 |
|---|---|---|
| 自动 | 大多数用户 | 优先使用可用的局域网路径，必要时使用 Tailscale；推荐作为默认选择 |
| 局域网 | 两台设备处于同一可路由网络 | 延迟最低；访客网络、客户端隔离和跨子网可能阻止发现或连接 |
| Tailscale | 设备不在同一地点或局域网不互通 | 两端都要安装并登录 Tailscale，并能在同一 Tailnet 中互相访问 |

更改连接方式后，TailSync 会断开旧连接、清理发现缓存并按新模式重新发现设备，短时间内显示“已发现”或“正在确认”属于正常现象。

### 完成安全配对

1. 在两端都打开“设置 → 连接与设备”。
2. 点击“允许配对”。界面会显示剩余时间和失败次数。
3. 在设备列表找到对方，在其中一端点击“配对”。
4. 等待安全握手完成。
5. 对照两边的六位验证码和设备指纹。
6. 两边内容完全一致时，双方分别点击“验证码一致”。

请勿通过聊天软件把验证码发给远端后盲目确认。验证码用于确认当前屏幕前的两台设备正在建立同一条安全连接；不一致时应立即取消并重新开始。

配对完成后，TailSync 会固定对方的身份公钥。以后即使 IP 地址变化，也不需要重新配对。

### 理解设备状态

| 状态 | 含义 | 是否可以立即同步 |
|---|---|---|
| 已发现 `discovered` | 找到了设备地址，但还没有收到有效探测响应 | 通常不可以，等待探测或检查网络 |
| 正在确认 `confirming` | 之前在线，最近一次探测失败，正在排除瞬时抖动 | 可能可以 |
| 在线 `online` | 最近收到 TailSync 服务的有效响应 | 已配对并启用后可以 |
| 已连接 `connected` | 当前存在通过身份认证的加密连接 | 可以 |
| 离线 `offline` | 连续两轮探测失败，且没有认证连接 | 不可以 |

TailSync 不会把残留的 mDNS 或 Tailscale 在线记录直接当成“应用在线”。后台大约每 5 秒探测一次，正常情况下设备断线后约 8–12 秒会显示离线。

### 管理已经配对的设备

每个设备条目都可以：

- 查看配对状态、设备指纹和当前路由；
- 查看 LAN、Tailscale 或 Iroh 候选路径的状态与延迟；
- 点击测试按钮检查具体路径；
- 单独停止或启用发往该设备的同步；
- 撤销配对。

“撤销配对”会删除本机保存的对端信任信息，但不会远程删除另一台设备的数据或历史。需要彻底解除双方信任时，请在两端分别撤销。

## 日常同步

### 同步文本

像平时一样在任意应用中复制文本即可。TailSync 检测到新的本机剪贴板内容后，会把它发送给所有已配对、已启用且可达的设备。

远端设备收到后：

- 将文本写入系统剪贴板，可直接粘贴；
- 在本地历史中保存一份加密记录；
- 在允许通知时显示系统通知。

TailSync 会抑制回传：远端写入系统剪贴板的内容不会立即被当作新的本机复制再次发回原设备。

如果一条内容因断线重试而变得过旧，TailSync 会放弃发送并显示提示，避免用旧内容覆盖对方更新的剪贴板。

### 同步图片

可以从截图工具、图像编辑器、浏览器或其他支持图片剪贴板的应用复制图片。图片到达另一端后会直接进入系统剪贴板，并在历史列表显示缩略图。

单个图片协议负载上限为 32 MiB。超大图片可先保存为文件，再使用文件同步。

### 同步文件和文件批次

1. 在 Finder 或文件资源管理器中选中一个或多个文件。
2. 使用系统的“复制”命令。
3. 保持 TailSync 运行，等待另一端显示传输进度。
4. 批次完成后，在另一端的 Finder、文件资源管理器或支持文件粘贴的应用中粘贴。

文件传输支持：

- 每批最多 20 个文件；
- 每批总计最多 1 GiB；
- 1 MiB 分块；
- BLAKE3 完整性校验；
- 分块 offset ACK；
- 断线和应用重启后的续传；
- 将整个批次作为一个剪贴板操作提交；
- 从历史中整批恢复。

历史窗口和托盘菜单会显示当前文件、目标设备、已传输大小、速度和批次进度。点击“停止”会取消当前批次，并尽量通知发送端停止继续传输。

未完成批次会在历史中标记为“未完成”，不能使用“全部复制”。其他已成功保存的历史不受影响。续传用的临时文件和状态最多保留 24 小时。

## 使用剪贴板历史

### 打开历史

可以使用以下任一方式：

- 点击菜单栏或系统托盘中的 TailSync 图标；
- 从右键菜单选择“历史记录”；
- 按全局快捷键：macOS 为 `Command+Shift+H`，Windows 为 `Ctrl+Shift+H`；
- 在设置中录制自己的历史快捷键。

历史记录保存在当前设备上，不是一个由服务器集中管理的云历史。删除本机历史不会删除其他设备上的副本。

### 搜索和筛选

历史列表支持：

- 关键词搜索；
- 按内容分类筛选；
- 按日期范围筛选；
- 分页浏览；
- 按今天、昨天、本周、本月和更早分组。

TailSync 会自动把内容分类为：

| 分类 | 常见内容 |
|---|---|
| 文本 | 普通段落、备注、自然语言 |
| 网站 | URL、域名、本地开发地址 |
| 代码 | 常见程序代码或配置片段 |
| 命令 | Shell、PowerShell 等命令行内容 |
| 结构化数据 | JSON 对象或数组 |
| 路径 | Windows、macOS、Unix 路径和 `file:///` 地址 |
| 图片 | 系统图片剪贴板 |
| 文件 | 单文件或文件批次 |

某些内容可能同时显示主分类和“文本”辅助分类，方便在分类不完全确定时仍可找到它。

文本正文不会以明文预览写入数据库的 `description` 列。关键词搜索在本机读取并解密正文后完成。

### 恢复、删除和置顶

历史行的常用操作：

| 操作 | 结果 |
|---|---|
| 单击 | 选择该条记录 |
| 按空格 | 在独立窗口中预览所选记录 |
| 双击 | 恢复到系统剪贴板 |
| 右键 | 删除该条记录 |
| 点击行尾图钉 | 置顶或取消置顶记录 |

置顶记录不会因历史数量限制或存储配额而被自动清理，但仍可手动删除。大量置顶文件会持续占用配额；如果配额中没有足够的非置顶内容可清理，新文件批次可能被拒绝。

标题栏图钉控制的是“历史窗口保持在其他窗口上方”，与记录置顶是两项独立功能。

点击搜索框右侧的垃圾桶可清空当前设备的全部历史。该操作不可撤销，并会同时清理关联的图片和文件存储。

### 使用文件批次

同一次复制的多个文件会作为一个批次展示：

- 列表默认折叠较长批次；
- 点击“展开剩余”查看所有文件；
- 完整批次可点击“全部复制”一次性恢复；
- 未完成批次会显示已收到数量和“未完成”状态；
- 在预览窗口中用上一项/下一项按钮，或 `Alt+←`、`Alt+→`，浏览同一批次。

## 使用独立预览窗口

预览窗口与历史窗口相互独立，因此预览时仍可继续搜索、筛选、翻页或选择其他记录。每个 TailSync 进程只复用一个预览窗口；再次预览会替换其中的内容，而不会不断创建窗口。

### 打开与关闭

1. 单击历史行选中内容。
2. 按空格打开预览。
3. 按空格或 `Esc` 关闭预览；输入框、搜索框或其他交互控件获得焦点时，这些按键仍归控件使用。

预览窗口不是全局置顶窗口。历史窗口最小化时，预览也会跟随最小化；历史窗口关闭时，预览随之关闭。不同预览类型会分别记住窗口大小和位置，并确保窗口仍位于当前屏幕的可用区域。

### 支持的内容

| 类型 | 预览能力 |
|---|---|
| 普通文本 | 选择文字、内容搜索、自动换行、字体大小、复制全部、行数和字符数 |
| 源代码 | 行号、本地语法高亮、文本/代码模式切换 |
| Markdown | 标题、段落、列表、任务、引用、代码块、分隔线和表格的文章视图 |
| 图片 | PNG、JPEG、GIF、WebP；适应窗口、缩放、平移、旋转、透明背景、尺寸信息 |
| PDF | 翻页、异步搜索、缩放、选择文字和按需缩略图 |
| DOCX | Windows 本地渲染；macOS 使用原生预览路径 |
| PPT/PPTX | macOS 验证文件签名后通过 Quick Look 预览 |
| SVG | macOS 使用锁定的离屏网页视图，Windows 使用带沙箱的 WebView2 iframe 渲染；两端都可在顶部切换图像/源码，并按条目明确允许外链；渲染期间显示加载占位，超时或失败时回退为源码 |
| XLSX 等其他格式 | 显示文件元数据，仍可恢复到剪贴板后用系统应用打开 |

在 Windows 上使用 `Ctrl+滚轮`，在 macOS 上使用 `Command/Control+滚轮`，可改变指针所在文本、图片或 PDF 的字号/缩放，同时保留普通滚动操作。

### 预览失败时

TailSync 会区分以下情况：

- 内容正在加载；
- 内容超过 64 MiB 预览上限；
- 文件类型不支持；
- 内容损坏或格式无效；
- 加密存储内容已不可用；
- 临时读取失败。

只有可能恢复的临时错误才显示“重试”。即使无法预览，只要存储内容仍可安全恢复，底部的“恢复到剪贴板”仍然可用。

## 暂停和恢复同步

可以从托盘菜单、设置页或全局快捷键暂停/恢复本机同步：macOS 默认为 `Command+Shift+S`，Windows 默认为 `Ctrl+Shift+S`。

设置中的“剪贴板同步”控制本机是否把新复制的内容广播给已启用设备。设备列表里的开关只控制对应设备，因此可以保留配对关系但临时不向某台设备发送。

更改快捷键时：

1. 点击当前快捷键；
2. 按下包含 `Ctrl`、`Alt`、`Shift`、`Command` 或 Windows 键的组合键；
3. 确认保存；
4. 如果提示冲突，换用未被系统或其他应用占用的组合键。

同步快捷键和历史快捷键都可以恢复默认或清除。录制期间 TailSync 会临时挂起旧快捷键，取消录制后恢复。

## 设置说明

### 通用

- 剪贴板同步：控制本机是否发送新复制内容。
- 同步快捷键：全局暂停或恢复同步。
- 历史记录快捷键：从任意应用打开历史窗口。
- 通知：控制远端内容到达时是否显示系统通知。
- 进度条：控制历史窗口是否显示文件传输进度。

### 历史记录

历史上限可设为 10–500 条，默认 100 条。达到限制后，TailSync 会优先删除最旧的非置顶记录及其关联内容。

### 存储

默认存储配额为 10 GiB。可以查看当前数据目录、已用空间和配额，并把批量历史数据移动到其他磁盘或目录。

更改位置时，TailSync 会：

1. 等待当前文件传输结束；
2. 检查目标空间；
3. 将数据复制到目标父目录下的 `TailSync Data`；
4. 校验文件与 SQLite 数据库；
5. 保存新位置并切换；
6. 在失败时尽量回滚到原位置。

原目录不会立即自动删除。确认新位置工作正常后，可在设置中选择“删除旧数据”；需要自行备份时则选择“保留”。迁移期间不要退出 TailSync、拔出目标磁盘或让设备休眠。

如果配置的外部磁盘不可用，TailSync 会显示存储警告并暂停文件接收，避免把数据写到意外位置。重新挂载磁盘后再刷新或重启 TailSync。

### 外观与语言

显示模式包括：

- 跟随系统；
- 浅色；
- 深色。

五套内置主题：

- Canvas：暖纸色、衬线展示字体；
- Flux：青色系、几何无衬线、紧凑圆角；
- Ledger：绿色系、书籍式衬线；
- Aura：玫红系、柔和大圆角；
- Mono：灰阶、零圆角、等宽展示字体。

界面支持简体中文和 English。系统开启高对比度、减少动态效果或减少透明度时，TailSync 会尽量自动响应相应的辅助功能偏好。

主题和显示模式是当前设备的本地偏好，不会同步到其他设备。

## 导入自定义主题

TailSync Theme V2 使用 `.tailsync-theme` 主题包。主题包可以改变颜色、字体、密度、圆角、材质、动效、组件状态，并可提供受限的 PNG/JPEG 标志、空状态图和预览占位图。

### 安装

1. 打开“设置 → 外观 → 自定义主题”。
2. 点击“导入主题”。
3. 选择 `.tailsync-theme` 文件。
4. 查看浅色、深色、高对比度浅色和高对比度深色预览。
5. 阅读诊断和候选版本信息。
6. 确认安装，再从主题卡片中启用。

### 更新、回滚和删除

- 更新：为已安装主题选择新的主题包。
- 同版本替换或降级：TailSync 会额外要求确认。
- 回滚：恢复到上一次成功安装的主题包。
- 删除：移除自定义主题；如果删除当前主题，会自动切回 Canvas。

主题包缺失、损坏或不兼容时，TailSync 会安全回退到默认主题，不会阻止历史和同步功能运行。自定义主题不会自动发送给其他设备，需要分别安装。

主题是声明式数据，不会执行其中的脚本或 HTML。TailSync 会拒绝未知文件、路径穿越、危险 URL、超限图片和不支持的格式。

## 检查和安装更新

Windows 和 macOS 均可在“设置 → 更新”查看当前版本、检查更新并安装；macOS 也可从菜单栏菜单选择“检查更新”。

TailSync 会验证更新签名，并应用更新通道和降级保护。正式发布版固定 TailSync updater 公钥；开发构建则有意关闭正式更新通道。若开发构建无法检查更新，请到可信发布来源手动确认新版本，不要安装无法验证来源的更新包。

预发布版本不会进入稳定更新通道。安装成功后按界面提示重启 TailSync。

## 隐私与安全须知

### TailSync 保护什么

- 配对使用限时窗口、六位验证码和双方确认；
- 每台设备具有持久化的 X25519 身份；
- 连接使用 Noise XX 身份握手和 ChaCha20-Poly1305 加密；
- 文本、图片和文件历史由系统保护的数据密钥加密；
- 文件历史使用 1 MiB 分块 AES-256-GCM 容器；
- 删除历史时启用 SQLite `secure_delete` 并截断 WAL；
- 协议会校验消息时间戳、消息 ID、ACK 和文件哈希；
- 认证失败不会降级为旧版明文连接。

### 仍然会出现明文的位置

系统剪贴板本身必须向其他应用提供可粘贴的数据，因此当前剪贴板内容会以操作系统允许应用读取的形式存在。除此之外：

- 正在接收的文件会在 `incoming/` 中形成临时明文 `.part` 文件和续传状态，最多保留 24 小时；
- 从历史恢复文件时，会在 `clipboard-files/` 中生成系统剪贴板所需的临时明文文件；未被剪贴板引用且超过 10 分钟后会定期清理；
- macOS 使用 Quick Look 预览 Office 文件时，可能在私有预览目录短暂生成权限受限的明文文件；
- 历史记录的类型、时间、来源和大小等元数据不加密。

如果设备会被多人使用，建议同时开启系统磁盘加密、屏幕锁定和独立用户账户。

### 预览安全

- Markdown 不会自动加载远程图片、媒体、框架、脚本或样式；
- 链接只有在用户明确点击后才交给系统浏览器；
- SVG 不交给 Quick Look 执行：macOS 用系统浏览器引擎在离屏 WKWebView 中渲染，Windows 用带空沙箱的 WebView2 `srcdoc` iframe 渲染。Windows iframe 不允许脚本、表单、顶层导航或访问宿主页面，CSP 默认封锁网络请求，仅保留内联样式和 `data:` 图片/字体；两端都受 8 MiB 输入、4096 像素边长、1600 万像素和 4 秒超时上限约束，渲染期间显示加载占位，失败时回退为内存中的源码视图。顶部的"信任外链"开关可按条目放开**仅 HTTPS** 的外部图片和字体加载——默认关闭、切换条目即重置；启用前会弹窗列出将被联系的具体 HTTPS 来源；非 HTTPS 目标和私网/环回/链路本地等非公网 IP 地址（包括浏览器支持的十进制、八进制、十六进制简写），以及 `localhost.`、`printer.local.` 等带 DNS 根尾点的本地域名会被明确拒绝且无法启用信任。信任模式 CSP 只列出本条 SVG 已批准的精确 HTTPS 来源并保留非默认端口，未披露域名即使绕过扫描也无法发起请求；带用户名/密码的 URL 会被直接拒绝；外部样式表、HTTP、媒体资源与 blob 地址始终拦截。启用信任是事务式的：只有可信渲染真正完成（macOS 安装新快照、Windows iframe 完成加载）后界面才会显示"已信任外链"，失败或超时都会回滚；待确认授权同时绑定当前条目的身份和内容，切换条目时不会在状态重置前短暂继承外链权限。两端共享同一套 SVG 策略（由 shared/svg-preview-policy-fixtures.json 固定并被两端测试共同断言）：含脚本、meta refresh、框架或动画的活动标记会在创建任何网页视图/iframe 之前直接归类为源码视图并显示原因提示，超限文件同样只显示源码，仅临时渲染失败提供重试；macOS 输出受像素预算约束的位图快照、Windows 显示实时矢量 iframe，安全策略一致但巨幅或深度缩放的文档观感可能不同；
- Windows 会在内容替换和窗口关闭时撤销内存 Blob URL；
- 预览在解密前后都检查 64 MiB 大小上限。

## 连接与配对排障

### 设备完全没有出现

按顺序检查：

1. 两端 TailSync 都在运行，而不只是 Tailscale 显示在线。
2. 两端选择了兼容的连接模式；首次使用建议均设为“自动”。
3. 局域网模式下，两台设备能够直接路由，且没有访客网络或客户端隔离。
4. Tailscale 模式下，两端已安装、登录并加入可互访的 Tailnet。
5. 防火墙允许 TailSync 使用 UDP `19889` 和 TCP `19890`。
6. 点击“刷新设备”，等待至少两个健康检查周期。

mDNS 通常不会跨路由器广播。比如 `192.168.31.x/24` 与 `192.168.1.x/24` 默认属于不同子网；请配置网络路由，或改用 Tailscale。

### 显示“已发现”，但不能同步

“已发现”只代表获得了地址，不代表对方 TailSync 服务已响应。请：

1. 确认对端 TailSync 仍在运行；
2. 点击该路由旁的测试按钮；
3. 检查 TCP `19890` 是否被防火墙阻止；
4. 等待状态变为“在线”或“已连接”；
5. 检查该设备是否已经安全配对并启用同步。

### 无法点击“配对”

设备当前没有可用的配对地址。请重新发现设备，检查所选连接方式，或在两端重新开启配对窗口。使用 Iroh 端点配对时必须处于“自动”模式。

### 验证码不一致

不要确认。立即取消两端配对，关闭再重新打开配对窗口，并确认选中的是正确设备。如果反复失败，检查是否有同名设备或旧实例仍在运行。

### 已配对但显示“无法同步”

设备列表会给出更具体的原因：

- “请先完成配对”：双方确认尚未完成；
- “该设备同步已暂停”：打开该设备右侧开关；
- “没有已保存的连接路径”：刷新设备或让对端上线；
- “版本不兼容”：把两台设备都升级到使用相同 v4 协议的版本。

同时检查全局“剪贴板同步”是否已暂停。

### Tailscale 不可用

确认 Tailscale 已安装、已登录且命令行/服务可以正常读取本机状态。TailSync 显示的离线状态以 TailSync 自己的探测为准；Tailscale 显示 `Online` 并不保证对端 TailSync 正在运行。

### 休眠唤醒后暂时离线

TailSync 会在唤醒后取消陈旧连接、重新建立连接并重置剪贴板监听。先等待两个健康检查周期；仍未恢复时点击“刷新设备”，然后检查网络接口或 Tailscale 是否已经完成重连。

## 同步与文件排障

### 文本或图片没有到达

1. 确认全局同步已开启。
2. 确认目标设备的独立开关已开启。
3. 确认状态为“在线”“正在确认”或“已连接”。
4. 换一段新的测试文本，排除源应用提供了特殊剪贴板格式。
5. 查看是否出现“较早内容未发送”的提示；这是防止旧内容覆盖新剪贴板的保护。

### 文件传输被拒绝或停止

检查：

- 文件批次是否超过 20 个文件或 1 GiB；
- 接收端磁盘空间是否足够；
- 存储配额是否已满；
- 是否有大量置顶记录占满配额；
- 外部存储是否仍然挂载；
- 文件名和源文件是否仍然有效、可读且未在传输中被修改。

TailSync 会清理文件名、限制入站连接和批次数量，并在最终哈希不一致时拒绝文件，避免把损坏内容写入历史或系统剪贴板。

### 进度条消失但文件没有粘贴

打开历史记录查找该批次：

- 显示完整批次时，点击“全部复制”重新恢复；
- 显示“未完成”时，等待对端重新连接以续传；
- 存储不可用时，先恢复存储路径；
- 单个文件损坏不会阻止在预览窗口浏览同批次的其他文件，但不完整批次不能整体恢复。

## 历史、主题和更新排障

### 搜索不到已知内容

先把分类和日期筛选都改为“全部”，清空关键词后重新输入。文本搜索在本机解密后执行；文件名和描述的匹配方式可能与正文搜索不同。

### 历史迁移警告

旧版 v1 数据按内容哈希幂等导入。损坏条目不会阻止应用启动；原 `history.db` 和 `.fernet_key` 会保留，并在下次启动时重试。不要在确认新历史完整前手动删除旧文件。

### 自定义主题突然恢复为 Canvas

所选主题包可能缺失、损坏或与当前 core 版本不兼容。重新导入可信主题包，或在设置中选择另一套主题。主题故障不会损坏历史、身份或配对数据。

### 无法检查更新

开发构建不会启用正式更新通道，网络或更新清单也可能暂时不可用。确认当前版本后，从可信 Release 页面手动检查，不要关闭更新签名验证。

## 端口与限制速查

| 项目 | 当前值 |
|---|---|
| LAN/Tailscale 发现与健康心跳 | UDP `19889` |
| 配对、认证与剪贴板传输 | TCP `19890` |
| macOS 外壳与本机 daemon | `127.0.0.1:19889`，仅 loopback，并校验能力令牌 |
| 文本负载上限 | 1 MiB |
| 图片负载上限 | 32 MiB |
| 文件分块 | 1 MiB |
| 文件批次 | 最多 20 个、总计最多 1 GiB |
| 历史上限 | 10–500 条，默认 100 |
| 默认存储配额 | 10 GiB |
| 单项预览上限 | 64 MiB |
| 未完成传输保留时间 | 最多 24 小时 |

macOS 本机 API 只应绑定 loopback，不要通过端口转发、代理或防火墙映射把 `127.0.0.1:19889` 暴露给其他设备。

为了更快定位问题，请记录：

- 两端 TailSync 产品版本和协议版本；
- 操作系统版本；
- 两端选择的连接方式；
- 设备状态与具体候选路由状态；
- 路由测试结果和延迟；
- 问题发生在文本、图片还是文件；
- 文件数量和总大小；
- 是否刚发生休眠、网络切换、存储迁移或应用更新；
- 界面显示的完整错误信息。

请勿公开分享验证码、设备私钥、应用数据密钥、完整剪贴板正文或包含敏感文件名的截图。
