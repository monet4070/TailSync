## 1. 推荐的产品定位

围绕两个任务完成闭环：

1. 浏览帖子时复制选中的文字和图片，TailSync 保存为一条历史；能够阅读预览，并从历史恢复到支持图文的目标应用。
2. 从文本编辑应用复制内容，之后通过 TailSync 恢复时，尽量保留目标应用原本能够接收的文本格式。

推荐选择“保留粘贴格式、提供简洁图文预览”。预览采用统一排版；已经安全捕获的原始格式继续保留并优先用于适用的恢复路径。预览支持的样式数量不决定保存和粘贴允许保留多少格式。

不建议继续把完整网页还原、复杂 Office 对象编辑、任意应用私有格式转换当作这两个任务的完成条件。也不建议退回纯文本加独立图片，因为那会丢失图文顺序和编辑器格式。

## 2. 当前实际能力与主要缺口

| 环节 | 已有源码能力 | 当前边界 |
| --- | --- | --- |
| 原始保存 | 原生快照及原始格式归档；与便携表示、派生内容区分 | 来源没有提供的内容不能凭空恢复；受捕获和预算限制 |
| 格式恢复 | 同平台满足条件时优先原件；便携表示有 Text、HTML、RTF、PNG | 目标应用选择接收哪种格式；资源完整性和平台能力会限制恢复 |
| HTML 预览 | 基本段落、列表、简单表格、按位置排列的本地图片；粗体、斜体、下划线、删除线、上下标和有限颜色 | 不支持完整 CSS；当前颜色只接受部分十六进制写法，混合 CSS 声明可能使颜色也失效 |
| RTF/RTFD 预览 | 原生分析可提供正文和部分附件 | 逐段样式与表格结构未完整映射；Windows helper 不具备 AppKit RTFD 分析能力 |
| 阅读结构 | 当前模型含段落、表格、图片 | 没有独立标题、引用、代码块或超链接目标字段，不能宣称已支持这些语义 |
| 网络图片 | 手动下载公开 HTTP(S) 静态 PNG，再保存和绑定 | 还没有默认关闭的自动下载设置；JPEG/WebP 等网络图片不在当前归档范围 |
| 原始图片 | 已有多种原始图片编码保存与静态封面路径 | 原件保存、网络下载、静态预览和动画播放是不同能力 |
| 跨设备 | 已有便携复合内容路径 | 完整原生同步、下载后资源补全传播以及目标应用效果必须分别验证 |

优先需要改变的地方：

- **资源缺失可能阻止整条默认恢复。** 原生 HTML 有外部依赖时会进入物化检查，便携内容仍未闭合时返回 `resources_incomplete`。当前“默认复制”与“完整离线归档”结合得过紧；这不是只改一条提示就能解决的问题。
- **预览简化被当成异常。** 两端 UI 都可能把普通 `styles_partial` 归因为原生样式缺失，并展开多个重复技术提示。
- **基础阅读功能尚不完整，长尾方案已经较复杂。** 超链接、标题和常见 CSS 强调映射，比来源授权文件桥、复杂对象转换更直接服务当前需求。

上述判断来自源码；没有读取用户历史数据库或系统剪贴板，没有重新执行 GUI、真实网页或跨设备验收。

## 3. 保留三项职责，减少用户需要理解的概念

### 保存与粘贴

保留来源实际提供、符合现有准入规则的 HTML、RTF 和安全原生格式。RTFD 作为已有 macOS 原生路径保留，不为它新增通用跨平台解析器。文档编辑器导出的剪贴板格式是支持对象；DOCX、PDF 文件解析不是本轮范围。

默认复制在原件可恢复时使用原件，避免用简化预览反向重建剪贴板。举例：编辑器中的“18 号宋体红色粗体”可以在预览里用统一字体展示；恢复时仍应优先交付保存的原格式，由目标应用决定接受程度。

### 图片及其他依赖

已经包含在剪贴板中的图片直接归档；只提供 URL 的图片按联网开关处理。下载内容作为派生资源保存，保留来源原文及位置关系。预览打开本身不触发外部请求。

### 简洁预览

沿用现有统一文稿模型，两端遵循同一支持清单。以阅读、识别和核对内容为目标；统一字体、正文大小、行距、背景和图片宽度。不新增“原网页/高保真/兼容/简洁”等多套预览模式。

## 4. 样式选择

以下是建议的目标支持清单，不能当作全部已经实现。第一轮先修已有支持的质量，再补最常见的阅读结构。

| 内容或样式 | 粘贴侧 | 预览侧选择 |
| --- | --- | --- |
| 正文、段落、换行、中文及 emoji | 保留来源可恢复内容 | 必须支持，优先验证无丢字、无乱序 |
| 图片和出现顺序 | 保留已捕获或已保存的资源与绑定 | 必须支持；缩放适配窗口，缺图在原位置标记 |
| 粗体、斜体、下划线、删除线 | 原格式保留 | 核心支持；HTML 标签和常见内联 CSS 都归一化到同一属性 |
| 有序/无序列表 | 原格式保留 | 支持常见层级，限制深度；不追求源应用编号模板 |
| 标题 | 原格式保留 | 建议补充三级统一视觉层级；更深标题映射到最低层级 |
| 超链接 | 原格式保留 | 建议补充文字与地址；仅用户点击才打开允许的 HTTP(S) 地址 |
| 引用、行内代码、代码块 | 原格式保留 | 建议补充简洁样式；代码保留换行和空格，不做语法高亮系统 |
| 文字颜色、文字高亮 | 原格式保留 | 支持普通实色并适配可读性；仅文字高亮，不模拟网页背景、透明混合或渐变 |
| 上标、下标 | 原格式保留 | 保留已有支持，不扩大为公式排版系统 |
| 简单表格 | 原格式保留 | 维持并改善基本行列阅读；不承诺合并单元格、嵌套布局、公式或源宽度 |
| 字体名称、精确字号、行距、页边距、精确对齐 | 原格式能够安全恢复则保留 | 统一为 TailSync 阅读样式，不因此提示失败 |
| 浮动、分栏、定位、背景图、外链字体、复杂 CSS | 原件按现有准入规则处理 | 不实现；有正文时继续阅读，装饰简化不反复报警 |
| 脚本、iframe、交互组件、嵌入对象 | 继续执行现有格式和发布限制 | 不执行；对象承载正文信息而无法展示时，提示该内容未展示 |
| 动画、多页图片 | 保留现有可保存原件 | 第一版静态封面；不新增播放器或多页阅读器 |

这里的收缩主要发生在预览排版与长尾适配。HTML 和 RTF 仍须保留：网页和编辑应用往往提供不同的剪贴板表示，删去其中一种会直接损害这两个场景。

小型 CSS 白名单只识别明确的强调、文本装饰、实色和上下标；识别等宽意图时可归一化为代码字体。未知属性单独忽略，不因为同一 `style` 中出现不支持的字号就连已支持颜色一起丢弃。不实现完整层叠、选择器或样式表引擎。

## 5. 网络图片与缺图时的复制

### 自动保存网络图片

沿用用户提出的单一设置：“自动保存网络图片”，默认关闭。以下任务范围为本方案推荐值，尚非用户已确认的产品行为：

- 开启后，后台处理新复制到本机的记录；不扫描旧历史，不因收到远端记录而再次自动联网。
- 旧条目保留“保存图片”手动操作。关闭设置停止新任务并取消未完成下载，已保存资源保留。
- 第一批覆盖公开 PNG、JPEG、静态 WebP；解码后可复用当前内部静态 PNG 兼容资源，不要求立刻扩展所有协议编码。原始字节保留和派生体积均受配额约束。
- 保留现有地址检查、并发、字节、像素、超时和重定向预算；先沿用现有限额，通过选定帖子样本评估覆盖率后再调整。
- 第一版不要求用户安装扩展，不自动使用浏览器登录凭据。登录图片、blob、未写入剪贴板的懒加载图片作为明确边界。
- 下载图片属于历史内容，计入现有存储配额；预览派生缓存应可重建。不要把已保存的离线图片当作构建缓存清理。

**默认关闭联网，就不能承诺所有帖子图片复制后自动离线可用。** 浏览器可能只把图片地址写入剪贴板。这项约束应在设置说明里直说；补齐图片格式和开关能够改善公开图片场景，不能保证任意网站。

### 不让一张缺图阻止全部可用内容

推荐改为按真实效果提供默认复制：

1. 原件完整且能够恢复：按现有原件优先路径复制。
2. 原件恢复受外部资源限制，但有可信且可独立使用的正文/格式/部分图片：生成独立的兼容副本，保留可用部分；复制反馈明确“已复制已保存内容，1 张图片未保存”。
3. 没有足够可信的可用内容，或发生存储损坏等实际失败：仍明确失败，不冒称成功。

第 2 项是需要实现和验收的新行为：保留缺图的位置及可用说明，移除未闭合的外部加载依赖；原记录、原始格式和缺失状态不被重写。不能只删除 `dependencies_complete` 检查，也不能给不完整记录伪造“完整”状态。预览简化不自动成为此兼容副本的格式上限。

这能让默认关闭联网时仍有合理的基本体验。后台下载完成只更新该历史记录，不自动改写用户当前剪贴板。下载完成后的跨设备补全应单独接入现有同步路径，并验证离线恢复；本地保存成功不等于另一台设备已有图片。

## 6. 界面选择

- 历史列表以首图缩略图、正文摘要和既有操作为主；普通条目不展示格式数量、协议、来源证明等信息。
- 预览默认就是简洁阅读页；正常的字体、字号和装饰简化不显示警告条。
- 缺图在图片位置写“图片未保存”；顶部最多一条汇总，例如“2 张图片未保存 · 保存图片”。关闭自动下载不应被描述为下载失败。
- 截断或正文解析失败明确提醒；技术原因合并去重后放到详情，避免中英文重复显示。
- “预览做了简化”“原件没有保存完整”“图片尚未保存”分别表达，不能用一个“完整性异常”概括所有情况。
- 来源证明仅在影响当前展示、导入或恢复决策时给用户可操作的提示；不要因未采用的备用表示缺少证明就笼统说正文未显示。后台检查继续保留。
- 将来源授权/文件桥移出普通历史操作的主要入口，作为实验或诊断功能保留。此建议不删除已保存资料或撤销既有授权。
- 普通用户不需要选择 HTML/RTF/PNG 或配置每种样式；纯文本复制作为次级能力保留，不新增一排格式按钮。

## 8. 建议的执行顺序与完成标准

### 第一轮：让当前体验可用且不吵

修正提示归因和重复展示；区分正常样式简化与真实内容缺失。设计并实现缺图条目的可用内容复制语义，覆盖原件、派生副本和当前剪贴板保护。

完成标准：缺一张图不影响阅读其余正文；有可信可用内容时能够明确复制可用部分；无静默丢图、假完整或旧任务改写新剪贴板。

### 第二轮：做通帖子图片路径

实现默认关闭的自动保存设置、PNG/JPEG/静态 WebP 下载、队列取消、配额和预览刷新。先完成本机闭环，随后把下载完成后的远端补全作为独立可验收任务。

完成标准：受控公开帖子含三种编码、多张有序图片，开启后新记录自动保存；关闭后不自动联网；已保存的同一条目在来源关闭、重启和断网后仍能预览，并在选定支持目标中恢复图文。部分失败仍能使用其余内容。

### 第三轮：补齐阅读常用语义

修好现有强调/颜色映射，再补标题、链接、代码/引用和适量原生样式映射。保持统一视觉，不扩大为通用 CSS 或 RTF 排版引擎。

完成标准：语义标签与等效常见内联 CSS 的基础强调一致；链接可识别且仅点击后打开；代码换行空格保留；未支持装饰不产生常驻错误。原件粘贴效果不因预览统一样式而下降。

### 第四轮：用目标应用决定继续投入什么

先选一款常用浏览器和两款实际编辑应用，以自造公开样本比较“直接粘贴”与“经过 TailSync 历史恢复后粘贴”，目标应用及版本保持一致。验证文字、格式、图片数量和顺序；来源关闭、重启、断网条件分别记录。跨设备需求再加入真实接收端和 Windows，不把本机通过推广为全平台通过。

直接粘贴已不支持的能力作为来源/目标组合边界；直接粘贴支持而历史恢复丢失的能力列为修复对象。频繁影响两个核心场景的失败才重新进入来源适配或复杂格式计划。
