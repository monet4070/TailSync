## 3．网络边界：S1-P1-4 与 S1-P1-5

**S1-P1-4：**手动配对输入已拒绝无作用域的链路本地 IPv6，但候选解析仍可能以 `SocketAddr::new(ip, tcp_port)` 构造无 scope 的地址。最小修复是使所有不能携带作用域 ID 的候选入口一致拒绝它；只有打算完整保存接口作用域并传入连接层时，才支持链路本地 IPv6。测试手动输入与发现候选两条路径。

**S1-P1-5：**`broadcast_targets()` 总加入 `255.255.255.255`，因此“广播目标为空”不是现有实现可达的测试。当前 `discover()` 至少一次 `send_to` 成功即返回 `Ok((local, peers))`，`peers` 可能为空。调用方已经能区分“至少发出一次”和“零设备”，却无法获知是否存在合格 LAN 接口。先明确 UI 或健康状态是否需要该接口事实；如果需要，在结果契约中表达，测试“全局广播发送成功但没有合格接口”“发送成功但零设备”“所有发送失败”。如果产品不需要独立接口状态，就保留返回契约并以测试和台账说明，不凭空增加字段。不得把正常的零设备视为发送失败。

增加 Windows 原生断网、虚拟网卡和 VPN 混合场景记录；单元测试无法代替这些设备结果。

## 4．配对持久化与匿名可见信息

**S3-P1-2：**信任可能先于双方确认落盘。设计可持久化的 `pending` / `active` 状态，定义重启、重复确认、超时、ACK 丢失和新旧版本互通规则。通过已认证连接继续确认或对账；不要仅因超时删除本地信任，因为对端可能已保存而确认丢失。故障注入覆盖每个持久化与发送边界，两端 UI 不把 `pending` 表示成已配对。测试夹具须包含冻结的旧版握手/持久化格式，与新版按**旧→新、新→旧**两个方向运行；旧端不理解新状态时应有明确拒绝或安全回退，不允许静默显示成功。

**S3-P1-1：**先按 LAN mDNS、UDP、Noise Message 2 和各连接模式列出匿名方实际可获得的字段，运行最小匿名发起者实验并制定允许公开的字段清单。Message 2 不是被动监听可读的明文；主动 XX 发起者可以取得它。如果隐私目标更严格，发现与握手要一起修改并评估协议兼容；仅移动 Message 2 字段不能自动消除发现阶段已有的暴露。

**S3-P1-3：**固定身份校验已受保护；目前未复现“未认证发现直接改写持久地址”的调用链。先记录可复现的输入和持久化证据；没有证据则按已排除子问题关闭，不预加地址来源状态。

## 5．文件配额与 SQLite 生命周期

**S4-P1-3：**当前淘汰循环每删一组就递归扫描一次物理存储，调用期间持有数据库锁。先测扫描次数和锁等待，再以一次物理空间基线、可证明释放的外部文件字节数以及不确定时重测来减少重复扫描。`file_batch_admission_lock()` 已串行化批次清单校验、pending 字节核算及配额预留；改变扫描或 I/O 位置时必须**保持**这一既有不变量，并用并发双批次测试证明不会重复认领空间。移出数据库锁的扫描必须在重新持锁后校验受其他历史写入影响的状态；不能只凭批次准入锁就假定全数据库不变。

**S5-P2-2：**删除已提交后即使 checkpoint 忙，也不应把删除报告为失败；但现有 `execute_batch("PRAGMA wal_checkpoint(TRUNCATE);")` 会丢弃返回的 `(busy, log, checkpointed)` 行，`busy=1` 走不到 `Err` 警告分支。将这一个调用改为 `prepare` + `query_row`（或等价的返回行读取 API），忙时留下可验证的警告或诊断并保持删除成功。用两个连接和持有中的读事务制造忙，降低测试 busy timeout，分别验证忙与正常完成。此项现在是“部分处理”，不能只添加断言旧 `Err` 分支的测试。

同一 PR 对 `db/storage.rs`、`db/migrations.rs` 和 `db/lifecycle.rs` 里其他丢弃 checkpoint 行的调用做影响核对，尤其是存储迁移在 checkpoint 后复制数据库及 WAL 文件的路径。先写出各处忙时应继续、重试还是中止的语义；若发现独立数据一致性问题，另开小 PR 和故障测试，不借 `S5-P2-2` 扩大成未经验证的重构。

**S5-P2-1：**另开 PR 清理外部孤儿文件。确认没有数据库引用、不是正在进行的传输且经过宽限期才删除；测试提交后文件删除失败、进程重启和重试。数据库行删除并不证明物理空间已释放。配额与孤儿清理分开审查。

## 独立的旧入口与文档清理

主线 `docs/USER_GUIDE.zh-CN.md` 已准确说明 Windows Tauri IPC，不重复改写。旧端口事实应重点核对双语 README、`windows/scripts/check_cross_platform_sync.mjs`、Windows `API_PORT` 常量及未启动的旧 transport。UDP `19889` 仍是发现端口，不能机械删除所有 `19889` 字样。

`shared/scripts/migrate_v1.py` 当前确实用 `socket.create_connection(("127.0.0.1", 19889))`；Windows 生产不启动该 API，macOS 生产使用私有 Unix socket 且有父进程 PID 校验。它是**目前无法按默认方式对生产客户端工作的手工恢复入口**，不能仅写“待确认是否仍拨号”。**第 1 阶段另开一个小型文档/工具 PR，由仓库维护者按“废弃旧手工入口、优先验证自动启动迁移”的默认路线处理**：脚本和两端包装入口先明确报出不受支持及可行恢复路径，不再引导用户拨号；自动迁移须有真实旧库夹具和恢复结果测试。若产品明确承诺继续支持手工恢复，则另设受支持、已认证的导入通道与端到端测试，不重新开启生产 TCP API。重新打开条件：用户文档仍指示旧脚本可直接运行，或自动恢复无法覆盖承诺的旧数据。

`macos/src-tauri/tray-helper` 包含旧 TCP 端口实现；本次仓库搜索未发现构建或调用它的引用。**第 8 阶段的清理 PR**先核对 SwiftPM 包、构建脚本和最终安装包清单；若仍无引用，移除这个孤儿组件并验证 macOS 构建、托盘行为与包清单不变。若发现真实入口，再按活代码审查并另开修复，不把目前未构建的源码直接登记为线上监听缺陷。重新打开条件：安装包或构建图仍引用它。

## 历史验收样例的替代门禁

白皮书第 5 节不得直接作为当前测试清单：单批最多 20 个文件、总计最多 1 GiB，因而“6 GB 单批”不可达；接收磁盘准入需要 `incoming_bytes + encrypted_copy_bytes + 64 MiB`，不能只用 `.part` 未完成字节判断“空闲 700 MB 应通过”。将样例改成上限内的边界、分批压力、有效 `.part` 续传及加密副本空间测试。性能断言采用固定负载、至少多轮记录和第 1 阶段冻结的预算，不照搬 1 ms 等易抖动阈值。

## 各开放项的通过与重新打开条件

下表是台账条目的最低约束；实现 PR 可增加更严格断言，但不得把测试通过与安装态、真机通过混写。

| ID | 通过条件 | 重新打开条件 |
|---|---|---|
| S1-P1-4 | 手动与发现候选都拒绝无作用域链路本地 IPv6，或端到端正确携带 scope ID | 任一路径仍生成不可拨号的 scope 0 地址 |
| S1-P1-5 | 契约决策已记录；零设备、全部发送失败及无合格接口的可观察行为分别有测试 | UI 或健康状态把“无可用 LAN”误报为已发现/连接成功 |
| S2-F5 | 冻结负载下永久丢文本事件数为 0，延迟与水位满足事先批准的预算 | 同负载再次超过预算或出现永久丢帧 |
| S3-P1-1 | 匿名可见字段矩阵与隐私策略一致，主动探测和各发现模式的夹具通过 | 匿名方拿到策略标为认证后可见的字段 |
| S3-P1-2 | 双方故障点、重启、重复确认及旧→新/新→旧夹具通过；单边 `pending` 不显示成功 | 单边记录被视为 active，或兼容性路径静默成功/失信 |
| S3-P1-3 | 固定身份测试通过；持久路由写入的未认证复现不存在或已修复 | 发现输入能改变持久信任地址而未经认证 |
| S4-P1-3 | 相同淘汰周期不再反复全树扫描；物理字节账目、双批准入及锁等待满足测试 | 双批重复认领空间、空间账错误或恢复重复扫描 |
| S4-P1-4 | 锁等待满足冻结预算且进度顺序正确；若超标则锁外回调后达标 | 同负载等待再超预算或回调顺序/完成语义倒退 |
| S5-P2-1 | 无引用孤儿在宽限期后可清理，活跃或受引用文件均保留，重启后可重试 | 孤儿过期仍占空间，或误删仍受引用文件 |
| S5-P2-2 | busy 返回列被识别并记录诊断，删除保持成功；非 busy 可完成截断 | busy 静默通过、删除被误报失败或 WAL 结果未核对 |
| S6-P2-1 | 队列覆盖/daemon 重启后客户端明确获知 gap/实例变化并重取快照 | 漏通知却继续使用旧游标而无提示 |
| S6-P2-4 | 隐藏期及进行中的轮询均不吞警告，前台恰好展示一次 | 警告丢失或重复展示 |

第 8 阶段的重构通过条件是：状态所有权和生命周期图可核对、两端既有行为测试全绿、关键路径耗时与错误契约无回退；重新打开条件是再次出现两份需手动同步的业务规则、状态源不唯一或平台错误语义漂移。第 7 阶段的数值预算由仓库维护者兼发布负责人在第 1 阶段批准；没有冻结预算不得宣布性能项关闭。

## 每个 PR 和最终发布的验收

PR 描述写明审计 ID、核对主线的完整 SHA、触发条件、改变后的行为、具名定向测试、运行结果，以及未做的原生或双设备验收。对安全和正确性修复，至少一次回退修复或注入故障证明门禁抓得住原问题；低风险文档、观察性改动不强制运行昂贵全矩阵。覆盖率定期收集，PR CI 按受影响平台运行，触及共享 Core/schema 则保留双平台矩阵。

最终双设备验收的执行责任人是**仓库维护者兼发布负责人**；每次验收在记录中写明操作者、两台设备与安装包 SHA。以**同一源码 SHA 的最终打包产物**验收 LAN/Tailscale 配对、双方重启、断线续传、网络切换及跨版本行为；另记 macOS VoiceOver、Windows 原生设置、安装态旧端口、来源证据和发布验证。没有设备或负责人签名时保持发布门禁待验。CI 绿、便携包 smoke 与安装态/真机结果分别报告，不互相替代。

台账条目关闭条件是：当前代码事实、回归门禁、适用的平台验收和文档状态一致。尚未取得的设备证据保持“待验”，不能因合并 PR 自动改成通过。
