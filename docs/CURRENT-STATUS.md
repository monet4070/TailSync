# TailSync 当前进度与下一步

更新：2026-09-24。依据当前分支源码、已提交的测试记录及本次 GitHub 查询整理。本文是进度入口；具体测试步骤见文末链接。状态发生变化时，请同时更新证据和本页。

## 30 秒看懂

**目标：**修好跨平台同步与 O08 错误/传输契约，让同一版 macOS 和 Windows 成品包可以安全互通、兼容旧版，并达到发布验收门槛。

```text
本轮 O08 功能代码 ✅ → 本机自动化 ✅ → GitHub PR/CI 待完成 → 真机与旧版互通待完成
                                      → 签名包安装/升级待完成 → 发布验收 NO-GO
```

**当前结论：源码已提交并推送，发布仍为 NO-GO。** 最新 O08 功能已有实现和本机回归；尚无这一版源码在真实 Mac 上的 Swift 构建、双方成品包互通和正式签名包验收。不能把旧包或模拟网络测试当成新版发行证据。

## 还没有做完什么

按解除发布阻断的顺序推进：

| 顺序 | 待办 | 完成标志 |
|---:|---|---|
| 1 | **建立 PR 并跑 GitHub CI** | 以当前分支对 `main` 创建 PR；Windows 打包、macOS bundle/daemon、前端、契约与汇总门禁全部通过，保存 run 链接。当前 GitHub 集成无创建 PR 权限。 |
| 2 | **补齐原始 O08 类型契约范围** | 盘点本地请求 DTO、Swift 手写字典读取与真实 dispatcher 覆盖；把未迁移的请求加入共同生成源、fixture 与跨平台门禁。 |
| 3 | **Mac 原生验收** | 在真实 Mac 上运行 `macos/scripts/check_macos_sources.sh`，执行 Swift 测试和 release build；对同一候选 `.app`/DMG 运行 bundle 检查及文档 M1–M10。 |
| 4 | **Windows 新版成品包验收** | 用包含 O08 的干净源码重建包，记录 commit、SHA 和签名；在可销毁 VM/测试账户完成安装、正常退出、升级、卸载、重启、自启动和端口检查。 |
| 5 | **双设备及旧版互通** | 用真实 macOS/Windows 新版和可追溯 N-1 包双向传文本、图片、文件；验证 v4 回退、v5 协商、断线续传、LAN/Tailscale/Iroh 实际路径。多 Peer 场景需第三台设备。 |
| 6 | **故障与长稳验收** | 在产品进程验证接收批次各阶段崩溃/恢复、物理剪贴板广播、忙碌文件读取；采集 Windows WebView2 PDF 长时内存、macOS O10 新旧预览路径内存和跨平台混合负载资源曲线。 |
| 7 | **签名发行与最终裁决** | 对同一 commit、同一签名包完成签名/公证或相应发行级别检查、干净安装升级、全部失败项复测，并归档双方版本、包哈希、日志与截图；全部通过后才改为 GO。 |

如下一轮出现测试失败，先记录具体构建和复现步骤，再修复并重跑受影响的门禁。以上待办中的缺失设备、旧包或签名环境应标记 `BLOCKED`；实际失败标记 `FAIL`。

## 容易混淆的三件事

1. 旧实施状态文件写的“O08 仍部分完成、能力为 false”对应 2026-09-19 旧提交。当前源码两端能力已为 `true`，但真实产品验收尚未通过。
2. “支持 wire v5”指双方协商后使用 v5 数据帧；产品版本号目前仍为 `2.2.2`，与 wire 版本不是一回事。
3. 本机单测、模拟延迟和旧版 unsigned 包烟测只证明各自测试范围。要发布，必须验证由当前源码构建的同一候选包。
