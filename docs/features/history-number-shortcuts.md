# 历史记录数字取用与左右翻页 — 执行方案

日期：2026-10-30。状态：**双端源码已实施，自动检查结果与原生验收待完成项见[实施记录](../acceptance/history-number-shortcuts-2026-10-30.md)**。

本文基于当前未提交工作树核对，代码基线为 `620a963` 加本地改动。用户已批准按本方案实施；下方保留交互契约与分阶段要求，第 2 节记录实施前基础，实际验证结果以实施记录为准。它是[现有键盘取用流程](keyboard-history-retrieval.md)的增量；原流程的验收证据继续保留。

## 1. 目标与范围

缩短已有的取用过程：**呼出历史 → 按数字 → 回到原应用 → 自己粘贴**。

用户明确的交互约定：

- 呼出历史记录界面时，焦点放在历史条目上，首条记录显示选中状态。
- 只有焦点在历史条目上时，`1–6` 才用于取用，`← / →` 才用于翻页。
- 条目聚焦时按无修饰键 `f`，焦点转入搜索框。
- 每一页前六条记录显示数字编号，编号随该页显示顺序计算。

第一版保留每页 **30 条**的现有容量，只给前六个实际渲染的记录行编号。继续使用现有搜索、筛选、预览、回溯及原应用焦点返回能力。收藏窗口是共享组件的兼容性检查对象；本次新入口先限定在历史窗口，收藏现有默认焦点和按键行为保持其原规则。

这次不需要数据库迁移、网络协议、后端 IPC 或新全局快捷键。直接按数字沿用现有回溯，用户仍自行按系统粘贴键。

## 3. 焦点与按键契约

### 3.1 呼出历史

1. 沿用原逻辑捕获原前台应用，展示历史窗口。
2. 为本次呼出建立“条目焦点”意图；有数据时选中当前页首个显示条目，并滚动到该页顶部。
3. 无数据或正在首次加载时，焦点落在稳定的列表键盘容器；此时可以按 `f`，数字和翻页不执行操作。
4. 数据到达后选中首条；只有用户仍处于本次条目焦点意图时才落实列表焦点。用户已点击搜索、按 `f` 或切到别的窗口时，迟到结果不得抢回焦点。
5. 重新呼出时沿用现有搜索词、筛选和已加载页，不额外重置查询；重新选择该页首条并恢复条目焦点。

“条目焦点”必须同时体现为可辨识的行选中框和真实键盘控制。只设置选中 ID、实际焦点仍留在搜索框，不算完成。

### 3.2 按键表

| 按键 | 条目聚焦时 | 搜索框聚焦时 |
|---|---|---|
| 无修饰键 `1–6` | 恢复对应编号记录，采用普通 Enter 的完成规则 | 正常输入数字 |
| 无修饰键 `← / →` | 上一页 / 下一页 | 原生移动光标、选择或输入法处理 |
| 无修饰键 `f` | 转入搜索框并全选已有搜索词，方便直接替换 | 正常输入字母 `f` |
| `↑ / ↓` | 沿用现有上下选择与跨页规则 | 非组词状态下，`↓` 转入列表并选中首条；不额外向下跳一条 |
| `Enter` | 恢复当前选中条目 | 沿用现有对搜索结果的 Enter 取用行为 |
| `⌘Enter / Ctrl+Enter` | 沿用现有恢复并保留窗口行为 | 沿用现有行为 |
| `⌘F / Ctrl+F` | 保留现有进入搜索的快捷键 | 保留现有搜索行为 |
| 空格、Tab、Esc | 沿用现有预览、深读和退出层级 | 空格正常输入，其他按键沿用现有搜索及输入法逻辑 |

新入口只接受无 Command、Control、Option/Alt、Shift 的按键；Caps Lock 不视为这些修饰键。接受主键盘和可输出对应数字的小键盘；Windows 小键盘关闭 Num Lock 时不把导航事件解释成数字。不把 `Shift+数字`、全角数字或输入法候选键转换为取用命令。

按键作用域必须由**实际焦点**确认：仅历史记录行和列表焦点容器参与。日期输入、筛选菜单、行内按钮、更多操作弹层、确认框、引导浮层和独立预览正文均不属于条目焦点。窗口可见或某条记录有选中 ID，不能单独作为启用条件。鼠标点击行中的按钮也不能顺带启用列表快捷键。

中文组词时，按键先交给输入法。macOS 继续使用 `hasMarkedText()`；Windows 继续使用 `isComposing`、`keyCode === 229` 和现有 compositionend 宽限窗。

### 3.3 重复按键

- 数字取用、`f` 和左右翻页忽略系统长按产生的重复事件。
- 一次左右按键最多翻一页；按住不连翻，不缓存尚未完成的后续翻页。
- 上下选择保留现有长按移动体验。
- 回溯或删除进行中，数字和方向键不启动另一项操作。

## 4. 编号与恢复语义

### 4.1 编号由实际显示顺序决定

统一计算：`numberedIDs = renderedRecordIDs.prefix(6)`。

- 从每页顶部开始编号 `1–6`，不跨页累计。第二页也从 `1` 开始。
- 日期标题、文件批次标题、“复制全部”和展开按钮不占编号。
- 批次折叠后隐藏的文件不占编号；展开后参与当前页的顺序，后续行的编号同步更新。
- 只剩三条时仅显示 `1–3`；按 `4–6` 无操作，不转而恢复当前选中条目。
- 编号按本页全部已渲染行计算，不随滚动窗口重新编号。滚动查看后不会把屏幕顶端另一条重新变成 `1`。
- 搜索、分类、日期变更和后台刷新采用新结果时，编号与行内容在同一次 UI 更新中替换。
- 焦点进入搜索后，编号可以保持显示但使用非活动样式；仅条目聚焦且查询可操作时显示为可用。不能只依赖颜色区分状态。

例如，列表为“文本 A、一个折叠的四文件批次、文本 B、文本 C”，显示顺序为：

| 显示内容 | 编号 |
|---|---|
| 文本 A | 1 |
| 批次标题与复制全部 | 无 |
| 文件 1 | 2 |
| 文件 2 | 3 |
| 展开剩余文件按钮 | 无 |
| 文本 B | 4 |
| 文本 C | 5 |

展开后，文件 3、文件 4 分别得到 `4`、`5`，文本 B 变为 `6`，文本 C 无编号。

### 4.2 数字只指向对应单条记录

按数字时从当前已提交到界面的编号表取出稳定 ID，设置对应选择，再调用现有单条回溯入口。不得重新查询“第 N 条”，也不得使用另一套原始数组下标。

- 文本、图片、图文和单文件按现有单条回溯规则处理。
- 文件编号对应**该文件行**；整个文件批次继续使用已有“复制全部”入口。
- 恢复完整成功：关闭历史与所属预览，返回原应用。
- 失败：保留窗口、当前页、查询及所选条目，展示已有错误信息，可重试。
- 部分内容已恢复：保留窗口和缺失提示，沿用当前反馈及显式重试规则。
- 数字入口使用现有恢复锁、复合内容 identity 与原始 ID 校验，避免新增重复发布路径。

### 4.3 编号视觉

数字固定在整条记录选中框的左上角，以记录边框为定位基准，不随缩略图形状或图标大小移动。14 pt 徽标中心对准框的左上角，外围保留空间避免裁剪；图片和图标留出顶部间距，保持完整可见。不为序号额外增加横向列。使用现有主题强调色、对比文字色与细分隔边框；不新增主题配置字段。未选中行的编号保持同样的行角位置。

列表区提供短提示：`1–6 取用 · ← → 翻页 · F 搜索`。搜索时提示改为 `↓ 返回条目`。中英文同步；辅助功能标签说明数字对应的恢复动作。

## 5. 左右翻页与异步状态

### 5.1 页面选择与滚动

- `←` 前一页，`→` 后一页；首页向左、末页向右不操作、不循环。
- 左右翻页成功后均选中新页首条，滚动到顶部，焦点留在条目区域，编号从 `1` 开始。
- 现有上下跨页规则保持区别：页底 `↓` 去下一页首条，页顶 `↑` 去上一页末条；首页首条 `↑` 保留原有进入搜索的行为。
- 鼠标分页与新左右键共用同一分页函数和边界判断，避免页码、选择和滚动规则分叉。
- 如果恢复过程中历史变化导致目标页不存在，沿用现有页码归一化能力；补齐两端空页边界处理后再发布，不能选中已不存在的记录。

### 5.2 一次翻页的状态转换

`当前页可操作 → 立即标记翻页待完成 → 请求目标页 → 成功提交新页 / 失败回到原页可操作状态`。

发起翻页时立即关闭数字和进一步翻页操作，不能等 React 的下一次 render 或异步任务开始后才加锁。旧页可暂留作视觉连续性，但其编号必须显示为不可用；不把等待期间按下的数字延后执行。

成功时原子更新页码、记录、编号、选中 ID 和查询标识，再开放操作。失败时保持原页数据和选择，撤销目标页意图、清除待选页边，并展示错误；**只有当前查询仍与原页匹配时**恢复原页操作。若同时改了搜索或筛选，旧记录保持禁用，直到新查询成功。

具体接线差异：

- macOS 的 `page` 当前在查询成功后才提交，已有 `pendingLoadPage`、`pendingPageSelection`、`loadGeneration`；沿用这些状态，增加左右命令，并统一鼠标分页。失败要清理待选状态，不能把“下一页首条”意图带入后续刷新。
- Windows 当前先 `setPage()`，再发起查询。需要保存已提交页/查询快照与同步翻页标记，或拆分请求页和已展示页；失败时恢复已提交页和查询标识，防止旧数据挂在新页码下，也避免回退触发无界自动重试。`queryReady` 本身不能防住同一批事件内第二次翻页。
- 查询代次与翻页标记绑定；旧请求的 `finally` 不能解除新请求的锁。
- `f`、搜索编辑、查询取消和关闭窗口继续可用；它们会使尚未提交的翻页意图失效。迟到页不能覆盖新查询或重新打开预览。
- 翻页后已打开的轻量预览跟随新选择，保持不夺焦；失败保留原预览。深读预览内的左右键和数字不控制历史。

## 7. 自动测试与人工验收

### 7.1 核心验收矩阵

下列场景在两端都需要覆盖；自动化优先使用注入历史与恢复桩，原生桌面行为另外实测。

| 编号 | 操作 | 预期 |
|---|---|---|
| K01 | 首次打开、关闭后重新呼出 | 当前页首条选中，真实焦点在列表；直接按 1 可取用 |
| K02 | 条目焦点按 `f`，输入 `f123`，按左右键 | 进入搜索、文本正常输入、光标正常移动，无取用或翻页 |
| K03 | 搜索按 `↓`，再按 2 | 第一次 ↓ 仍选首条；2 恢复编号 2 |
| K04 | 列表焦点按 1、6；三条结果按 4 | 分别使用编号 1、6 的稳定 ID；不存在编号无副作用 |
| K05 | 右翻一页、再左翻；首页向左、末页向右 | 每次一页，成功选首条并回顶部；边界无操作 |
| K06 | 翻页请求尚未返回时按 1 和再次按右；长按右 | 不恢复旧页，不排队执行，不跳过中间页 |
| K07 | 翻页失败；随后重试或按数字 | 页码、条目和选择仍为原页；原查询可用时数字可再次操作 |
| K08 | 翻页过程中按 `f` 搜索，新结果先返回、旧页后返回 | 不抢走搜索焦点，不覆盖新结果，不重开旧预览 |
| K09 | 数字后立即连按数字/Enter/分页；恢复失败或部分成功 | 仅一个恢复进行；完整成功才关窗；其余保留选择与反馈 |
