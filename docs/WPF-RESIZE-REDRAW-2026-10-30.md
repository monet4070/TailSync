# 调整窗口大小时的拖影 · 2026-10-30

用户确认症状只在拖动改变窗口大小期间出现，松开后消失。本轮调整原生窗口
与 WPF 重排后的重绘交接，保留现有布局、主题字体和硬件渲染路径。

`MacWindow` 在实际尺寸改变的 `WM_WINDOWPOSCHANGING` 中加入
`SWP_NOCOPYBITS`，让 USER32 丢弃旧尺寸的客户区像素。仅移动位置及
`SWP_NOSIZE` 操作不加该标志。消息继续交由 WPF 和 WindowChrome 处理，
保留框架在交互缩放时同步布局与呈现的过程。

WPF SizeChanged 后合并安排一次 Render 优先级的全客户区失效，使新布局
完成后的重绘覆盖旧画面占据的位置。缩放结束也补一次重绘。该过程不擦除
背景，不调用同步 UpdateWindow，不在每一帧递归强制布局。关闭窗口时取消
待处理回调。HwndTarget 的清屏色与不透明主题 Canvas 色保持一致。

进入原生移动/缩放循环时结束尚未完成的窗口入场位移动画，并取消当前滚动
惯性；用户缩放过程中内容不会继续受此前滚轮输入驱动。松开后正常滚动和
控件反馈仍可使用。没有给文字加缩放、位图缓存或效果，也没有切换到软件
渲染。

`--resize-check-dir=<目录>` 使用隔离 Rust 后端和合成历史记录。94 项检查
覆盖浅/深色的历史、设置和连接窗口，30 次真实 HWND 尺寸变化、完整客户区
更新区域、字体参数、底色和缩放前后滚动行为。附加 `--resize-review` 可保留
合成窗口，记录真实边缘拖动的原生尺寸消息及重绘次数。

交互验证记录包含 69 次尺寸变化及 33 次全客户区重绘。用户在实际连续拖动
后确认修复有效。截图仅为合成内容；这些计数不代表 GPU 帧率、端到端延迟或
显示面板响应时间。当前显示器验证不能代替不同 DPI 和显示器的验收。
