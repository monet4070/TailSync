# 图文恢复收敛：2026-10-09

## 产品目标

用户确认保留当前阅读预览，不追求网页 HTML 原貌；历史恢复应交付可继续使用的带格式文字和已保存图片。Word、备忘录、微信、QQ 是目标应用，但各应用能否接收混排内容必须分别实测，不能承诺所有聊天软件接受相同格式。

## 本轮执行范围

1. 保留安全且完整的原件恢复，避免破坏文本编辑器的已有格式。原件因资源依赖无法恢复时，先尝试既有可用内容路径；仍不闭合时，从历史原始载荷重新构造规范化图文副本，而不是从 UI 预览摘要截取内容。
2. 复用阅读文稿模型的段落、标题、粗体、斜体、下划线、删除线、颜色、高亮、引用、代码、列表和简单表格语义。忽略网页脚本、外部样式和复杂布局；已绑定的图片保持正文顺序，真实缺图保留占位并报告数量。没有来源关联的图片不能猜测插入位置。
3. 兼容副本提供文字和自包含 HTML；在预算允许时追加内嵌 PNG 的 RTF，供 Windows/文档编辑器选择。macOS 原生 RTF 读取器不保留本轮 PNG pict，故在发布前通过受监督的 helper 将已经验证闭合的 HTML 转成 RTFD，核对附件数量和序列化往返，移除会丢图的派生 RTF。恢复计划包含实际 RTFD 字节后才进入唯一发布路径。
4. 菜单只提供可恢复的“仅复制文字／仅复制图片”备用入口；纯文字不添加重复入口。公共图片归档改称“补全网络图片（点击联网）”，授权、导入、撤销放入高级菜单。仅外部引用显示“部分资源未保存”，不把 CSS 缺失误称为图片缺失。

## 安全与数据约束

- 不改原始历史载荷、身份、完整性或原件；不修改预览，也不更改网络图片开关的默认关闭状态。
- 损坏资源、未知原件缺失、native-only 摘要、正文／结构截断、超预算不冒充完整恢复。严格准入和外部依赖闭合检查保留。
- 图片内容来自已保存资源；恢复不下载网络图片。RTFD 准备在阻塞工作池中运行，不持有 engine 锁或原生发布许可等待转换；监督截止、输出上限、取消、内存租约及发布前 generation/revision 检查仍有效。
- helper 转换不读写剪贴板，附件缺失或转换失败时在任何剪贴板副作用之前结束。系统发布的 Partial/Unknown/Superseded 仍不能显示成功或自动重试。
- HTML/RTF/RTFD 是内部兼容载体，不向普通用户暴露格式选择。
