#### 2026-10-09 后续：每次复制都会弹出通知

- 当前实证：正在运行 `2026-10-09-qq-rich-text-01/TailSync.app`；只读生产历史库的最近复合记录 3124、3125 来源均为空，通知开关开启。API/Swift 模型没有把空来源转换为 `self`。这能解释显示复制内容的 TailSync 通知。

- 预期修复：本机复合采集正确标记来源，通知只提示真正的远端到达；保留错误和传输失败提示。正常本机复制保持安静的要求合理。本轮仅更新反馈与诊断，未改变设置、代码或正在运行的 App。

### F07：网络图片未显示，文稿降级提示频繁且难以理解

- 用户原话：“这是什么问题，为什么网络图片不显示呢，我发现这些错误提示基本在很多记录中都出现了，我们如何减少这种情况”。
- 用户观察：截图中正文与一张表情图片可显示，另一张图片显示“图片指向已保存内容之外”；文稿顶部同时出现重复的样式提示、英文技术细节、来源验证提示及原生样式/表格提示。用户报告类似提示在很多记录中出现，尚未统计发生比例。
- 类型：资源完整性与预览信息呈现问题；本轮仅只读分析代码和维护反馈，不实施产品修复。
- 合理性判断：合理。减少缺图与降低提示打扰应同时推进，不能仅隐藏提示或把未保存的内容标为完整。
- 当前代码确认：文稿预览只显示保存并绑定的图片，不联网加载外部引用；现有“保存图片（联网下载公开图片）”操作仅归档公开 HTTP(S) 静态 PNG，不带浏览器登录凭据。该记录的实际地址、图片格式、是否尝试过归档及服务端结果尚未取得，不能从截图认定为超时、防盗链或特定格式失败。
- 当前代码确认：HTML 的 span 样式只支持非常有限的颜色声明，其他常见声明可能触发降级；多个不同原因映射到相同中文提示且逐条展开。Swift 对任意 `styles_partial` 还可能补上“原生逐段样式与表格结构暂不可用”，将普通 HTML 样式简化误归因为原生结构问题。任一备用表示的来源未验证也会触发整份文稿的提示，而“未显示”的文案不精确反映实际正文仍可显示的情况。
- 建议方向：先修正提示归因、按用户影响合并并折叠技术细节；再在原有地址安全、解码和资源预算边界内拓展 JPEG/WebP 等常见公开图片的本地归档；对需要登录、blob 或来源上下文的图片复用明确授权的浏览器资源导入流程。历史条目的补全须另行授权，保留原始引用和内容，不静默联网或重写原始记录。
- 状态：已记录并完成上述源码核对；真实记录归档原因待确认，产品修复与原生验收未执行。

### F08：设置中增加默认关闭的自动下载网络图片开关

- 用户原话：“还有我想要把下载网络图片的做成一个设置中的开关，默认关闭，打开即自动下载网络图片资源”。
- 类型：功能与默认隐私行为要求；用户要求默认关闭，开启后自动处理网络图片资源。

- 当前代码状态：现有持久化设置中没有该开关；资源归档由显式命令触发，公开网络归档仅支持静态 PNG。剪贴板原始 JPEG/WebP/GIF/TIFF 的保存与静态封面能力，不代表网络下载已支持这些格式。
- 建议语义（未确认）：本机设置，开启后仅对新复制到本机且含外部图片的记录后台归档；不自动扫描旧历史，不因收到其他设备记录而自动联网。旧记录仍可手动补图；关闭后停止新增任务并取消未完成任务，保留已下载图片。下载结果作为本地派生资源保留，不修改原始剪贴板快照或用户当前剪贴板。
- 实施边界：需要串联持久化设置、两端设置契约/界面、后台有界队列、关闭取消、条目身份校验、存储配额及预览刷新，不是单加 UI 开关。建议首批公开图片范围明确为 PNG/JPEG/静态 WebP，并保留地址安全、字节、像素、超时和重定向限制。下载完成后的跨设备资源传播须单独定义和验收，不能由本地归档成功推断。
- 状态：已记录，尚未实施；开启后是否处理旧历史、远端记录以及跨设备补全行为仍需确定。
