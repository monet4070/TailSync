# ADR-008：首次发布前获取公开网页图片

- 日期：2026-10-29。
- 状态：已实施；本机原生／WebKit 验收通过，真实公网下载受当前代理 DNS 限制，双设备验收待完成，详见[最终记录](../acceptance/web-article-sync-2026-10-29.md)。
- 上游：[ADR-007](ADR-007-web-article-sync.md)、[ADR-005](ADR-005-composite-content-identity.md)。

## 决策

网页选区只有图片 URL 时，在首次同步事件冻结之前，复用公开图片归档器尝试取得字节。图片与正文仍是一个复合事件，图片按原节点绑定；首次发布之后的后台补全只更新历史，不再次自动覆盖系统剪贴板。

沿用现有“自动保存网络图片”设置，默认值及用户选择不变。只有本机新复制、来源确认为 External、观察时已取得有效网络许可的内容进入前置获取。旧记录、接收内容、自写／来源未知、MissingFormats 和过期许可不会因此自动联网；设置关闭或存储／恢复上下文失效时取消。

## 时限与降级

- 前置获取整体最多 2 秒，单次请求最多 600 毫秒；预留最后 100 毫秒物化已有结果。重定向、网络等待和解码均计入现有期限。
- 较晚图片的请求超时／总读取额度耗尽时，可保留已取得的图片；尚未取得的图片留在原位置，由 ADR-007 的可用副本恢复负责占位。
- 没有取得新图片或前置处理失败时，沿用原始采集和发布路径。后续仍可按现有设置后台归档。
- 为捕获与存储的复制工作区保留空间，前置获取只处理来源保留字节与当前便携内容合计不超过 16 MiB 的捕获。更大内容保留既有后台归档路径，不扩大 256 MiB pipeline 记账预算。
- 图片增强无法入库时，回退保存原始来源并按实际保存的便携内容发送；原始保存本身失败才进入原有采集失败／重试流程。

整体期限是前置图片阶段的边界，不是复制到目标应用的端到端延迟承诺。它不包含后续持久化、发现设备、实际传输或目标应用粘贴耗时。极端调度或物化超限时仍可能保守退回原始内容，不能伪造图片已完整。

## 原件、初始便携内容与事件身份

前置获取发生在本次历史入库和首个事件生成之前。MAC 原 CNA1 或 Windows 原生快照保留来源 HTML、格式与字节；已验证的网络资源派生关系只允许替换对应图片源，不能改写正文或绑定到无关位置。

新增入库入口把来源原件、补图后的初始便携内容及下载的 PNG／JPEG／静态 WebP 原件放在同一个历史事务中。复用已有 Manifest 5 的网络原件与资源层；初始资源层等于本次冻结的便携内容，初始 archive revision 仍为 1。网络或数据库中途失败不会留下一个宣称已保存图片、实际却缺少资源的成功行。

本次事件的 wire digest 对应**已经补图并持久化的初始便携内容**。它从生成开始固定；不先发送旧摘要，再修改相同事件 ID 的内容。CNA1 原件内容身份、原生来源指纹和 wire digest 继续分域。没有新增 frame、协议版本、数据库 schema 或应用设置。

macOS 的预览来源核验增加已验证的公开资源派生：来源投影必须相同，或仅把公开图片引用转成有对应资源的节点绑定；正文、已有图片资源或绑定遭替换仍拒绝。它验证的是本机受控采集的派生关系，不声称图片字节具备额外的来源签名证明。

## 后续归档更新

首次事件已经包含的图片不再导出成 ArchiveUpdate。首发部分图片成功、另有缺图时，后来归档只对冻结初始内容中仍未绑定的节点导出补充，摘要仍引用原来的首发事件。接收端据此补全同一历史，既不另建图文条目，也不重复写当前剪贴板。

初始网络图片的规范化 PNG 通过 composite 同步；原始 JPEG／WebP 下载字节在发送端保留。后续补充继续沿用原有 ArchiveUpdate 的原图编码支持。本轮不扩展 composite 的 MIME 集合。

## 并发、取消和预算

采集观察到新系统 revision、较新恢复 generation 或恢复上下文变化时，取消前置下载；旧来源可保存历史，但不能继续发送。发布仍经过原有 gate 复查。

取消、超时或调用方被丢弃后，尚在运行的解码线程继续持有网络 admission 与 capture memory lease，直到退出。发送准备在确有独占所有权时缩小 lease；存在尚未退出的图片线程时继续保守保留完整预算，不把其工作区提前从账上移除。

## 获取边界

支持公开 HTTP(S) 静态 PNG、JPEG、WebP，沿用地址／DNS／实际连接校验、凭据禁用、重定向、字节及像素限制。前置阶段不会读取 file、blob、登录凭据或懒加载中未写入剪贴板的内容。复杂 CSS 决定的视觉顺序与目标应用接收能力仍需独立验收。

2026-10-31 根据用户确认，图片可用性优先：DNS 命中 `198.18.0.0/15` 时保留按域名交给系统代理/系统网络路径获取的兼容分支，不因 Fake-IP 主动降级为缺图。普通解析结果仍沿用公网校验和固定 IP 直连；URL、重定向、响应类型、时限及解码预算继续生效。Fake-IP 分支允许代理重新解析目标，不将其描述为严格的公网 IP 绑定路径。

跨阶段额度由归档器统一计算：调用方传入已有网络原图和完整上限；已有原图字节、已有图片引用的像素与派生 PNG 字节只扣除一次。去重资源仍按每个引用出现计入归档额度，超限节点保留外链，已完成节点可继续原子提交。

## 本地验证

- 实际平台采集入口：首条事件已含 URL 图片、入库摘要与发送摘要一致、原始 HTML 仍保留、没有文字先发或第二个图片事件。
- 新复制／手动恢复打断等待：取消网络，保留来源历史，只确认旧 revision，不发送旧图文。
- 许可、来源、大小准入、关闭设置、取消、单请求与整体截止，以及部分图片完成后超时的降级。
- PNG／JPEG／WebP 与重复图片经首发帧、重开数据库、离线恢复，图片仍处于对应文字之间；首发部分成功后，归档更新只发送原来缺少的图片。
- 存储原子性：正文／图像替换被拒绝，网络原件写入故障不留下半条成功历史，原生来源与网络原件可重开读取。
- 解码线程取消后保留 admission 和内存预算；已有图文发布、副作用未知、重复投递和新复制保护回归继续执行。

本轮通过：Core 996 项单元测试（3 项跳过）及默认集成测试；Runtime 140 项单元／集成测试；macOS 采集入口 33 项（2 项可选矩阵跳过）；Windows 在 macOS host 上的采集入口 32 项；接收器故障补修与来源指纹回归 12 项。Windows host 输出保留 3 条既有 cfg 裁剪相关 dead-code warning，不把 host 通过当作 Windows 原生运行通过。

Core／Runtime 全 target Clippy、根 workspace 与两端格式检查、canonical include、跨平台契约检查、设置文案 JSON／Swift 语法检查均通过。

上述为第二批阶段结果。最终回归、WebKit／AppKit 验收及当前公网环境限制见[最终记录](../acceptance/web-article-sync-2026-10-29.md)，原生消费的结构化证据随文保存。构建日志与临时数据保留本机，不随产品源码上传。测试通过隔离器运行，没有修改用户 general 剪贴板、历史、设置或已安装 App；本机通过不替代 Windows 原生运行和双设备粘贴验证。
