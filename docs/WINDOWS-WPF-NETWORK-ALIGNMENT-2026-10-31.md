# Windows WPF 内核对齐与配对修复

日期：2026-10-31。保留当前 WPF 界面，以 `36533cc` 的 Windows 集成为起点，合入 GitHub `codex/clipboard-onboarding-fixes-2026-10-31` 的 `bc5ff769dbf0f969977c50b2d30dbe856909087e`。工作分支为 `codex/wpf-network-align-2026-10-31`。

## 复现与修复

1. **已完成事务的旧回执中断新配对。** 在两份隔离身份上运行当前交付的旧后台，先完成 Iroh 配对，再仅让一端忘记对方并重新配对。保留历史回执的一端抢先发送旧 nonce，另一端报 `Received pairing commit without matching durable intent` 并断开。修复后，`Completed` 回执仅在对方提出匹配恢复证明时回答；新验证码会话仍等待用户确认，未完成事务的恢复及禁用/撤销检查保留。
2. **验证码倒计时错误。** 原状态接口返回 120 秒配对窗口的剩余时间，实际验证码会话在 30 秒结束。将安装会话时确定的截止时间同时用于状态接口和两种提交路径，结束、取消、失败及重新开窗时清除会话截止时间。保留原有 30 秒会话上限。
3. **接入握手被监听循环取消。** 原 Iroh 监听在 `select!` 中等待完整 QUIC 握手；清理另一个连接、刷新模式或监听的五秒计时可能中断它。现在监听只接收可安全取消的 incoming，握手由独立任务完成，未完成与活动任务合计最多 64 个，仍保留总量与每来源限额。
4. **建连吞掉认证预算。** LAN/Tailscale 的 TCP 建连使用 10 秒，Iroh 的地址发现及 QUIC 建连使用 30 秒；连接建立后单独执行最多 5 秒 Noise 认证。普通配对和连接池使用同一策略，配对取消仍会立即取消未完成操作。
5. **等待配对阻挡设备选择。** WPF 的“允许配对”只开启接入窗口，保持设备列表可用；发起配对或出现验证码时才打开配对对话框。
6. **日志证据易丢失。** 默认减少 Iroh 逐包日志，记录实际配对失败原因，避免网络 span 迅速覆盖有用的配对日志。

本机现有 TailSync 防火墙规则为允许规则，未修改系统防火墙。以上旧回执复现不等同于已经远程读取 Mac 的配对状态；实机根因还需结合修复版上的双设备复测。

## 验证方式

- `windows/native-ui/check-wpf-network.py`：真实的两个 N0 Iroh 后台、命名管道 IPC、邀请、Noise、验证码、双方确认、分别单端忘记后重新配对，并交换邀请创建方和连接发起方。测试使用隔离身份与数据。
- Core：旧完成回执与新确认兼容、已完成回执响应丢失 ACK 的恢复、错误 nonce/公钥/撤销保护、准确倒计时、并发 incoming，以及配对后两端各自发起真实 QUIC/Noise 连接并交换认证心跳。
- 平台网络：慢 TCP/Tailscale 建连超过五秒后仍可配对、Noise 仍受五秒时限约束、取消和失败分类、连接池回归。
- WPF：实际按钮事件与 IPC、模式保存、接收等待时设备列表可用、验证码与超时状态、自包含发布及 helper 自检。
- 跨平台契约：共享网络 include 与双端编译接线保持同步。
