# TailSync 2.3.2

键盘优先的历史取用、存储降级可见性，以及一批配对、存储与投递正确性修复。线协议基础兼容仍为 v4（数据帧按连接协商 v4/v5）、数据库 schema 仍为 v11，已配对设备无需重新配对即可升级。

> 状态：**候选**。本文件描述 `fix/phase4b-storage-feedback` 上相对 v2.3.1 的改动；尚未打 tag、尚未发布。macOS 原生验收仅部分完成，Windows 原生与真实双设备验收仍待进行，详见「本次未包含」。

## 新功能

- **键盘优先的历史取用。** 全局快捷键唤起历史窗口后，焦点直接落在搜索框：第一次按 ↓ 把焦点交给列表且**仍选中第 0 条**，之后 ↑↓ 上下移动并跨页续接；空格在**不夺焦**的独立预览窗口里浏览，↑↓ 时预览跟随选中项；Tab 进入预览深读；Enter 恢复内容、关闭窗口并把焦点交还给唤起前的原应用；⌘Enter（Windows 为 Ctrl+Enter）恢复但保留窗口；Esc 分层——先关预览，再退历史。
  - 输入法组词期间 ↑↓/空格/回车/Esc 一律交还输入法，不会误触发恢复。
  - macOS 在搜索框自身的 `doCommandBy:` 里拦截按键，而不是用全局事件监听器；这是针对上一版真机失效（按键进了搜索框、列表毫无反应）的定向修复。
  - 历史行的键盘选中框改用主题 `history.focus` 焦点色，普通主题 2pt、高对比主题 3pt，且不再做淡入淡出——任意时刻只会有一行显示选中框。

- **存储降级状态持续可见。** 存储不可用时，历史窗口显示常驻提示条（而不是只在某次复制后闪一次 toast），设置页跟随同一份运行时快照显示状态；本地服务不可达时明确标记为「状态暂不可确认」，而不是继续展示一个过期的「健康」读数。存储恢复后，已打开的历史/收藏窗口会立即刷新，不再等到下一次无关的剪贴板事件。

## 安全与隐私

- **配对不再留下单边孤儿。** 双方确认后先落一份非权威的 pending 记录，只有在同一认证会话收到对端的持久化证明后才提交 active。新增能力门控的提交证明与认证对账（新命令 `0x0011`/`0x0012`，仅在双方都宣告该能力时使用），使「一端显示已配对、另一端毫无记录」的状态可以被恢复；能力未协商时完整回退到旧路径，旧端不会收到未知命令。
- **接收端重启后，旧事件不再覆盖更新的剪贴板。** 新增一个最小的持久化 sidecar `remote-event-receipts-v1.json`（位于身份/设置所在的私有数据根，与批量历史存储的迁移解耦）。键是**已认证的 Noise 静态公钥指纹 + 事件 ID**，摘要绑定命令、原始时间戳与内容：同 ID 改内容会被拒绝，同内容用新 ID 仍会被当作新意图。写入顺序为「先持久化 claim，再执行原生剪贴板 I/O」，因此崩溃后不会重复施加同一效果。这是 at-most-once 的**尝试**语义，不是 OS/SQLite 的 exactly-once 原子性。
- **存储降级时拒绝迁移。** 之前存储不可用会退化成内存库，此时执行存储位置迁移会把磁盘树复制过去并直接替换数据库，导致已被 ACK、已收藏的内存历史静默消失。现在降级状态下迁移与切换根都会在改动磁盘或设置之前失败；先恢复访问、等待历史合并完成，再迁移。合并按内容哈希幂等、在单个事务内完成，收藏取并集。
- **不再向用户暴露本地路径。** 文件选择被拒（含符号链接、文件夹）时，日志保留完整路径，用户界面只显示分类后的原因。
- **IPv6 链路本地候选缺少 scope 时不再被当作可用直连候选。**

## 传输与存储正确性

- **配额记账不再重复计入已落盘的续传前缀**，也不再依赖文件系统大小判断空间是否释放（SQLite 删除不会让数据库文件缩容，旧判据会误报「空间未释放」而拒绝合法传输）。
- **配额预检的扫描与锁等待**：全盘递归扫描改为每次预检只测量一次基线，并计入可证明的释放量。
- **WAL checkpoint 被读事务阻塞时不再静默。** 改为读取 checkpoint 的结果行，阻塞会被上报而不是当作成功。
- **孤儿外部载荷对账接入常驻维护任务**，不再只在启动时清理一次；对账按存活行核对，并防范仍在写入的临时文件。
- **v9 清理在读者阻塞 WAL 截断时会失败并重试**，不再无声跳过。

## 连接与投递

- **文件控制帧与即时事件分离为独立认证 worker。** 之前文件元数据等待可以打满 64 容量队列并丢弃剪贴板文本帧；现在两者各自有按需 worker，复用认证、路由、重连与撤销。文件故障只重建文件 lane。
- **投递失败路径补上退避**，网络闪断不再进入零延迟热重连。
- **Windows 端后台轮询不再「偷吃」同步警告**：警告改为按 ID 确认，且只有可见窗口才能确认，打开窗口时不会再发现警告已被后台消费掉。
- **运行时通知环形缓冲溢出可被检测**，中间被丢弃的错误提示不再无声消失。

## 界面与本地网络

- **发现结果仍然只是本轮候选**，持久路由只在完成固定公钥验证的握手之后更新（沿用 v2.3.1 的语义，并补齐了针对该信任边界的门禁测试）。
- **macOS 部署目标统一钉在 13.0。** 打包阶段新增 `check_macos_deployment.py`：扫描最终 `.app` 中每个真实 Mach-O、逐个 lipo 架构检查 `LC_BUILD_VERSION/minos` 或 `LC_VERSION_MIN_MACOSX/version`，任何 slice 超过声明值即让打包失败；缺元数据同样失败。此前 native helper 会跟随构建机默认值（在较新系统上变成 18），与声明的 13+ 不一致。

## 工程与门禁

- **新增可机器校验的整改台账**（`docs/remediation-ledger/`）：31 条缺陷各带状态、门禁测试与 CI job，由 `scripts/check-remediation-ledger.mjs` 校验「ID 集合、状态一致性、门禁测试确实存在、CI 确实执行该测试」。台账同时显式记录每条**尚未**验证的边界。
- 新增跨进程的剪贴板重启回归（真实 TCP/Noise/SQLite，两个独立进程与身份），并接入 CI。

## 本次未包含

- **Windows 原生验收全部未做**：原生安装/卸载、DPAPI、WebView2、原生剪贴板（含 CF_HDROP）、托盘、开机自启、真实中文输入法、前台窗口归还。本版 Windows 侧只有前端测试、生产构建与 macOS 宿主上的 `cargo check` 证据。
- **真实双设备验收未做**：配对、双向文本/图片/文件、断线续传、网络切换、跨机睡眠/唤醒。
- **VoiceOver 无障碍验收未做**（清单已备好：`docs/acceptance/voiceover-connections-checklist.md`）。
- **键盘取用历史的真机验收只完成了一部分**：仅「快捷键唤起 → 第一次 ↓ → 第 0 条显示选中框」经确认；T-01、T-02、T-03、T-05 ~ T-10 仍为待验，见 `docs/acceptance/keyboard-macos-native-2026-10-03.md`。
- **`S4-P1-4` 未修**：接收引擎锁内的平台进度回调仍在锁内调用。台账的 `pass_condition` 要求真实设备负载采样或把回调移出锁；目前只有注入式竞争实验（macOS 侧 200 样本、注入 50 ms 持锁，callback p99 55 144 µs），既不是真实负载也不是预算通过，见 `docs/acceptance/s4-p1-4-macos-measurement-2026-10-03.md`。
- **配对单边持久化仍为部分修复（`S3-P1-2`）**：提交证明让「一端 active、一端 pending」在双方重新打开配对窗口并完成认证对账后可以收敛，但**不保证任意失败序列后两端 active 状态永远一致**——不匹配的 consent、已撤销或已禁用的设备不会推进，不一致可能持续到人工恢复。
- **文件/事件队列隔离的性能预算尚未由维护者裁定（`S2-F5`）**：按命令拆分 worker 已实现，但拆分后的事件队列水位不等价于此前签署的共享 priority 水位，需要确认测量范围后才能完整关闭该条。
- **正式签名与公证未做**：本版按 Community 层级构建（ad-hoc 签名、未公证），首次启动可能出现 Gatekeeper 警告。
- **签名自动更新的首次闭环未验证**：更新包签名、SHA-256 与降级保护已实现，但尚未从上一个公开版本执行过一次完整更新。
