# Windows 预览窗口改为完整关闭（2026-10-11）

用户反馈：按 Esc 后预览消失，但历史数秒内不能操作；进一步怀疑透明顶层宿主仍拦截输入。此前的隐藏后五秒销毁流程与恢复时间吻合，但尚未在新包上完成实机复现与验收，不将此推断记录为已确认的唯一根因。

Mac 的 `HistoryPreviewWindowController.close()` 取消任务、清理预览内容、移除内容控制器、清空窗口引用并调用 `NSWindow.close()`；`closeAndReturnToHost()` 随后将键盘焦点交回宿主。窗口尺寸和位置另外保存，下次预览重新创建窗口。

Windows 采用相同的完整关闭、重新创建流程：

- 在 UI 线程先同步隐藏原生 HWND，并清除顶层标记，验证 HWND 已不可见；不再先隐藏 WebView2 内容而留下空宿主。
- 立即通过 Tauri 销毁窗口和 WebView2，不再对预览使用五秒延迟释放。预览宿主改为不透明窗口。
- 返回历史的原生与 WebView2 输入焦点，通知历史列表恢复 DOM 焦点。
- 快速重开异步等待原生 Destroyed 通知，避免复用正在销毁的窗口；连续关闭请求幂等处理。
- 历史、收藏、设置等其他短暂窗口的缓存策略保持原状。

自动验证：前端 64 文件、444 项通过；Windows Rust 136 项通过、3 项既有忽略。新增真实 Win32 可见顶层窗口测试验证生产关闭辅助函数清除可见性和顶层标记；控制器测试验证连续关闭和销毁前快速重开等待。便携包通过 v11→13 升级、helper、端口与单实例启动检查。既有六条历史、五个 payload、身份及配对配置核对一致。
