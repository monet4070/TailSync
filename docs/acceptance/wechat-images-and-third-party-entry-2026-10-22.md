# 微信图片复制与第三方图片入口（2026-10-22）

本机实际微信图片复制含一个项目：Absent public.file-url、空的 Qt text--uri-list / application--x-qt-image 标记、完整 public.tiff。
原 helper 已产生 PNG；旧逻辑因混合文件描述符拒绝便携投影，且原件发布指纹无法接受 Absent 格式，导致历史保存后不同步。

新增受限 Qt 静态图片结构识别，适用于观测到的微信格式，不把 Qt 标记当作应用身份认证。
要求稳定单项目、完整有效且预算内的静态 TIFF/PNG、空 Qt 标记和未读取的 file-url；不接受未知格式、非空 URI 列表、读取失败、动画、多页 TIFF 或多个项目。
仅对该结构的完整 macOS archive，在便携投影中移除 file-url；原件留存不变。
采集指纹使用独立 tailsync-origin-qt-image-observation-v1 域绑定原件及描述符；严格原件发布仍拒绝 file-url，来源冲突、未完成写入、自身写回保护保留。
转换使用既有 helper 产生的 PNG，无需目录权限或新增文件读取。

设置 → 历史记录 → 第三方应用图片提供可展开入口，包含 QQ 图片读取授权开关，以及微信“复制即用”的支持说明。
QQ 原有授权保留；微信明确说明逐张静态图片的范围，不宣称动态表情或多条消息合并复制已支持。

验证覆盖原失败结构、实际微信剪贴板本机回放、单次保存与单次发送队列、原件保留、来源保护，以及 QQ 权限状态回归。
真实剪贴板只在私有临时目录用于离线验证，不进入仓库、发布附件或网络，完成后删除。
用户已确认实际微信图片同步成功；随后反馈图片标题显示为通用富文本内容。

历史摘要现保留原件的图片摘要优先级（包括动画帧数），在完整、单项目且便携投影仅含一个 PNG 时，允许使用投影的格式和尺寸作为标题。空 Qt 元数据不再使纯图片回退成通用富文本标题。
旧记录在读取时通过已存储的 PNG 尺寸修正显示，不改写加密内容、原件或历史身份；多项目、不完整 archive、带正文或资源绑定的富文本不使用此回退。
回归覆盖旧版通用标题的普通列表与分页读取、原件/身份/密文不变、图片类型、保护条件，以及实际采集保存后的标题。
标题修正通过自动化回归；更新后的本机历史界面已显示原有微信图片的 PNG 格式、尺寸和单帧信息，不再显示通用富文本标题。用户已确认实际微信同步成功。
