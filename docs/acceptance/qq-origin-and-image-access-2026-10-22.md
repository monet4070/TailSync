# QQ 自动同步来源判断与图片读取开关（2026-10-22）

QQ 多图消息包含私有消息原件和未读取的 `public.file-url` 附带项目。
现有 QQ 转换接受这个结构并保存 HTML/文字/图片，但采集端复用的原件发布指纹要求每个格式都已捕获且可发布，
因此合法的新复制被归为 UnknownMismatch，保存历史后未自动同步。

修复在采集端增加受限的 `tailsync-origin-qq-observation-v1` 指纹域：只接受已识别的稳定 QQ 消息结构，
额外项目只能是 Absent 的 file-url 描述或控制字段；其余原件仍必须完整捕获并通过原有格式/大小策略。
指纹绑定原件字节、项目边界与描述符，移除修订号和控制字段并稳定排序。
它只用于采集分类，不进入发布指纹或原件恢复准入。原来的便携与原件发布指纹、线协议、数据库格式保持不变。
OriginTracker 的未完成写入、隔离与指纹冲突规则继续生效；QQ 转换后的便携内容写回仍按原指纹识别 SelfWrite。

设置页使用“读取第三方应用图片”开关，目前支持 QQ。有效的只读 bookmark 是开启状态；取消或授权失败不显示为开启，
撤销失败也不假装关闭。关闭会删除 bookmark，缓存读取必须持有匹配账号的授权，即使操作系统另有宽泛权限也不会绕过开关。
只保存复制消息里明确引用的、经过路径校验的 Pic 目录提示，不扫描账号。
系统授权窗口自动定位该目录；没有来源提示时要求先复制一条 QQ 图片消息，不再打开 Documents 让用户查找。
目录提示不能授予权限，实际读取仍需要用户确认 macOS 文件夹授权，并保留已有的只读、路径、软链接和预算检查。

新增回归先确认 QQ 来源指纹失败和未授权读取的旧行为，再验证修复。
采集流程测试覆盖真实隔离数据库与对端队列：两张图片和文字全部进入一个事件，没有来源不明警告；
Core 测试同时覆盖不允许原件发布、内容/描述变化、失败格式、非 QQ 格式、自身写回和未完成写入。
helper 测试覆盖自动目录提示、关闭/重新授权、账号范围与 bookmark 重启读取；Swift 测试覆盖开关的成功、取消、失败及状态刷新。

完整原始日志和安装包验证记录随本机 `macos/release/` 交付。合成回归不替代真实 QQ 消息、系统授权窗口及 macOS↔Windows 双机验收。

## 实际 QQ 剪贴板回放补充

首次修复只覆盖 file-url 在后续项目的合成结构，遗漏了 QQ 把该描述符放在消息项目（item 0）的真实结构。
本机复现采集到一个稳定项目：QQ 消息原件、QQ 附带元数据、Absent public.file-url、Captured public.tiff，
helper 已成功生成 PNG 和 QQ HTML/文字，原采集指纹却因 item 0 的 Absent 描述符失败。
修复将 QQ 专用的延迟文件描述符判断覆盖至所有项目；仍只允许 Absent public.file-url，
仍要求稳定、有效且包含已捕获 QQ 原件的结构，其他格式必须完整捕获并满足原来的大小/发布策略。
严格原件发布指纹不变；不会读取文件 URL 或将其发布给对端。
新增单项目来源回归、单项目两图片真实数据库/发送队列回归，以及对本次私有 CNA1 采集的本机离线回放。
真实采集只用于本机验证并在结束时删除，不作为仓库或发布附件保存。
